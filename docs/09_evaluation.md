# 09. 평가 방법론과 결과

> 기준일 2026-11-26. 근거: 내부 평가 보고서(골든셋 v3~v3.2 계획·동결 문서, 리랭커 사전등록·판정, 사람 눈가림 A/B 결과, 시뮬레이션·레드팀 보고). 평가 질의·정답·원자료는 이 저장소에 **포함하지 않는다**. 이 문서는 방법과 요약 수치, 그리고 **실패와 한계**를 적는다. 수치는 모두 표기한 날짜의 값이다.

## 1. 원칙

1. **목적은 정합성·신뢰성**이다. 평가는 «좋아 보이는가»가 아니라 «틀린 근거를 내지 않는가»를 본다.
2. **판정 기준은 사전에 등록**한다(결과를 보기 전에 합격선·지표·변형·표본을 고정). 시험(test) 세트는 최종 판정에만 한 번 쓰고 튜닝에 쓰지 않는다.
3. **순환 위험을 명시**한다. 정답이 평가 대상 시스템의 구조(예: 카드 술어)로 정의되면 그 시스템이 유리하다.
4. **표본이 작으면 작다고 쓴다.** 구간(부트스트랩 95%)을 함께 보고, 구간이 0을 포함하면 «불확실»로 쓴다.
5. 운영 API 에 부하를 주는 평가는 야간·저부하·가드 중단 조건을 두고, 프로세스 내 호출로 측정한다.
6. 실패한 평가와 철회한 결론도 기록한다.

## 2. 골든셋

| 항목 | 내용 |
|---|---|
| 구성 | v3.1 215건 + v3.2 225건 = **최종 440건**, 클러스터 421, **dev 314 / test 126**, confidence high 423 · medium 17 · low 0. 코퍼스별(법령·내규·단체협약·공시) 자연어 개념 질문, 기간 지정 공시, 법령 판본, 제목·조문 질의, 집합 질의 등 |
| 질의 작성 | **모델이 작성**했다(사람이 쓴 질의가 아님) |
| 정답 라벨 | **DB 조회로 기계 검증**(현행·비폐지 판, 기관 지정 질의만 협약 조항 라벨 등). 표본은 사람이 교차검수 |
| 동결 | 2026-10-25, 분할 해시로 소속을 고정(dev/test 소속 변경 0건). 시험 30%는 최종 판정 전용 |
| 채점 | hit@1/3/5/10, MRR@10, nDCG@10, recall@30·50. **정답을 doc_id 열거가 아니라 «본문 해시 동치류»로** 채점(같은 본문의 다른 판본·사본·형제 문서가 오답으로 깎이는 것을 방지), 이득 상한은 동치 집합 크기까지, 클러스터 단위 부트스트랩(4,000회) |

### 순환 위험·한계

- **라벨 불완전**: v3 교차검수 표본 30건 중 약 **20%가 보정 대상**(단체협약 약 40%, 법령은 낮음). 원인은 같은 본문의 다른 판본·사본·형제 문서가 정답에서 빠진 것이었다. 보정 레코드 18건(교차검수 확정 6 + 단체협약 전수 재계산으로 추가 8 + 주 라벨 교체 2 + 신뢰도 상향 2), 질의 문구 변경 2건. 단체협약 60건 전수 재계산에서 동치 문서가 60 → 78개로 늘고 2건이 강등되어 **정정 레코드가 10/60(약 17%)**이었다.
- **질의가 모델 작성**이라 모델의 어휘 습관이 반영되고, 라벨이 DB 와 «기계 검증»이라는 것은 사람 판단과 같지 않다.
- 질의 독립을 가정하나 같은 기관·같은 항목 질의가 많아 클러스터 상관이 있다(그래서 클러스터 부트스트랩).
- 기준선 요약은 n=40 안팎인 부분이 있어 구간이 넓다.
- 최신 분기 10건은 2026Q3 를 «공개된 것»으로 간주하는 결정을 반영했다(2026Q2 는 legacy).
- 질의 로그는 평가 집합으로 쓰기 위해 설계했으나 개인정보 우려로 한동안 보류했다([10](10_operations.md)).

## 3. 사전 등록 합격 기준 — 리랭커(법령)

|---|---|
| 대상 | 법령(legal) **test 32건**, 질의 = 골든 자연어, 후보 = `semantic` 기준선 상위 10건 |
| 모델·변형 | KURE-Reranker-nano int8, `rerank_only` **단 하나**(dev 에서 4변형이 거의 같아 구조가 가장 단순한 것으로 사전 지정) |
| **합격 기준(판정 전 고정)** | 주 지표 hit@1·MRR 의 쌍체 Δ 95% 구간이 **모두 0을 배제(하한>0)** 이고 서버 p95 ≤ 3초 → «법령 한정 도입 근거 있음». 하나라도 아니면 «근거 불충분»(결과 그대로 보고, 재시험·튜닝·변형 교체 금지) |
| 결과(2026-10-26) | hit@1 **0.219 → 0.531**, MRR **0.349 → 0.573**(95% 구간 하한 > 0), 서버 p95 **2.2초** → **통과**, 법령 한정 반영 |
| 한계 | 표본 32건·클러스터 소수라 구간이 넓다. **전체 코퍼스 semantic 기준으로는 효과가 없었고 내규 hit@1 이 유의하게 하락**했다 → 법령 외로 확대하지 않았다. hybrid 법령은 test 미검증. 법령 semantic 지연 +1.3~1.9초 |
| 이전 시험(실패에 가까운 결론) | 2026-10-25 로컬 시험(n=30, 후보 30): MRR +0.066 · nDCG@10 +0.072 로 방향은 긍정이나 **전 지표 95% 구간이 0을 포함 → 도입 보류(조건부)**. 외부 호스팅 재랭커 시험(10-21)도 같은 결론 |
| 내규 | 2026-11-26 현재 «그림자 모드»(점수만 기록, 응답 불변). 3일·200건 판정 뒤에만 적용 여부를 결정 |

## 4. 사람 눈가림 A/B (2026-11-26)

| 항목 | 내용 |
|---|---|
| 질문 | 사례 카드(`find_cases`)가 있을 때와 없을 때(일반 검색) 답의 유용성·근거 신뢰도 |
| 평가자 | **1명**(서비스 기획자) — 가장 큰 한계 |
| 설계 | 20질의, 세트당 최대 8건, A/B 위치 무작위, 눈가림(제목 길이·말줄임 일부가 달라 **불완전**) |
| 결과 | 유용성(1~5) **3.90 vs 2.65, +1.25(95% 구간 +0.65~+1.90)**, 근거 신뢰도 3.55 vs 2.80, 더 나은 쪽 카드 14 · 카드 없음 4 · 동등 2. 위치 편향 없음 |
| 하위 집합 | 골든 10(카드 술어로 정의 → **순환 위험**) +1.8(8승 2패), **새 자연어 10 +0.7(6승 2패 2동등, 구간 넓음, 경계)**, 노출 코드 17 +1.29, 카드 풀 시험 3건 +1.0 |
| 해석 | 사전 확대 승인 조건 ① «A/B +15%p 이상»은 전체 +31%p(구간 하한 약 +16%p)로 충족했으나 **새 자연어만 보면 +17.5%p(구간 넓음)로 경계**. 조건 ② «카드 풀 밖 on-topic 20건 표본에서 카드가 있었다면 유효 사례 ≥70%»는 **미실시**. 중단 조건(카드 없음이 카드보다 −5%p 이내)은 해당 없음 |
| 카드의 약점(평가자 메모) | 발췌에서 결론이 빠짐, 핵심 사실이 잘림, 조건부·제안 단계가 섞임, 결과 필터가 불가능한 질의(예: 성과급 지급 보류)에서는 둘 다 낮음 |

## 6. 시뮬레이션 (2026-11-26) — 가상 사용자 업무 과제

| 항목 | 내용 |
|---|---|
| 방법 | 페르소나(노조·인사·감사·경영평가·규정제정·연구자/기자) 업무 과제를 LLM 으로 생성(110과제), 소형 추론 모델이 **클라이언트**로 운영 MCP 를 읽기 전용으로 호출(도구 최대 8회), 판정자도 같은 계열 모델 |
| 실행 | **55과제만 실행**(호출 한도와 도구 8회 상한 충돌), **35과제 판정** |
| 결과 | 사전등록 성공 **16/35(46%)**, 부분 8(23%). 감도 분석(반복 호출 규칙·고지 정규식 완화) 시 66% → **46~66% 구간**으로 읽어야 함. 규칙 지표 통과 65% |
| 유형별 | single 60%, clause 75%, cross(기관 비교) 50%, timeseries 75%, **cases(사례 수집) 0/4**, legal 0/2, typo 1/3 (n=1~8 — 경향 이상으로 읽지 말 것) |
| 관찰 | search_corpus 가 호출의 77%. **한 번도 안 쓰인 도구**: `compare_documents`·`get_related`·`search_extra`·`query_sql`(internal 15과제에서도 0회). `structured_query` 오류 58%, `find_cases` 오류·0건 각 44%(클라이언트가 인자를 잘못 줌). 8회 상한 도달 65%. `hybrid`+`corpus=all` 은 p50 3.3~10초·최대 30초 |
| **인용 신뢰도** | 인용이 있는 32과제 중 doc_id 완전 일치 19건(59%); 형식 오류 제외·정규화 일치 23/28(82%). **실재하지 않는 doc_id 를 인용한 과제 약 18%** |
| 한계(먼저 읽을 것) | 가상 사용자 + **소형 클라이언트 모델**이라 실제 Claude 의 도구 선택·재시도와 다를 수 있다. 절대 성공률이 아니라 «응답·도구 설계가 약한 클라이언트에게도 통하는가»의 보수적 하한 근사. 판정자 자기선호 편향(5점이 63%). **사람 검수(표본 20장)가 끝나기 전에는 «품질» 결론 금지**(2026-11-26 시점) |


## 7. 그 밖의 검증

- **변환 A/B**: 같은 PDF 270건으로 파서 두 버전 비교 — PDF 32/150(약 21%) 상이, HWP·HWPX·XLSX 동일. 손실률을 본문 해시 기준으로 정정(16% → 4.2% → 0.8%).
- **검색 지연 실측**: HNSW ef_search 400 에서 recall 0.95~0.98(내규·법령·단체협약), p50 약 1초대.
- **경영평가 종합등급 추출**: 사전등록 기준으로 표본 검수, 외부 발표와 대조한 정정 반영(세부 수치 미수록).
- **A/B 가 못 하는 것**: 사람 평가자는 1명이고 질의는 20건뿐이다. 외부 이용자 만족도·장기 사용 데이터는 아직 없다(미확인).

## 8. 정직한 요약

- 법령 재랭크처럼 **사전 등록을 통과한 개선**은 적용했고, 통과하지 못했거나 불확실한 것(전체 코퍼스 재랭크, 내규 재랭크)은 적용하지 않았다.
- 사례 카드는 사람 눈가림 A/B 에서 유리했지만 **평가자 1명·순환 위험·풀 13%·재현율 약 71%**라서 «표본 기능»으로만 노출한다.
- 시뮬레이션 성공률 46~66%와 인용 오류 약 18%는 개선이 필요한 지점이며, 추정치는 클라이언트 모델에 크게 의존한다.
