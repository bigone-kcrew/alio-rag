# 09. 평가 방법론과 결과

> 기준일 2026-11-26. 근거: 내부 평가 보고서(골든셋 v3~v3.2 계획·동결 문서, 리랭커 사전등록·판정, 사람 눈가림 A/B 결과, 시뮬레이션·레드팀 보고). 평가 질의·정답·원자료는 이 저장소에 **포함하지 않는다**. 이 문서는 방법과 요약 수치, 그리고 **실패와 한계**를 적는다. 수치는 모두 표기한 날짜의 값이다.

## 1. 원칙

1. **목적은 정합성·신뢰성**이다. 평가는 «좋아 보이는가»가 아니라 «틀린 근거를 내지 않는가»를 본다.
2. **판정 기준은 사전에 등록**한다(결과를 보기 전에 합격선·지표·변형·표본을 고정). 시험(test) 세트는 최종 판정에만 한 번 쓰고 튜닝에 쓰지 않는다.
3. **순환 위험을 명시**한다. 정답이 평가 대상 시스템의 구조(예: 카드 술어)로 정의되면 그 시스템이 유리하다.
4. **표본이 작으면 작다고 쓴다.** 구간(부트스트랩 95%)을 함께 보고, 구간이 0을 포함하면 «불확실»로 쓴다.
5. 운영 API 에 부하를 주는 평가는 야간·저부하·가드 중단 조건을 두고, 프로세스 내 호출로 측정한다.
6. 실패한 평가와 철회한 결론도 기록한다.

## 2. 골든셋

| 항목 | 내용 |
|---|---|
| 구성 | v3.1 215건 + v3.2 225건 = **최종 440건**, 클러스터 421, **dev 314 / test 126**, confidence high 423 · medium 17 · low 0. 코퍼스별(법령·내규·단체협약·공시) 자연어 개념 질문, 기간 지정 공시, 법령 판본, 제목·조문 질의, 집합 질의 등 |
| 질의 작성 | **모델이 작성**했다(사람이 쓴 질의가 아님) |
| 정답 라벨 | **DB 조회로 기계 검증**(현행·비폐지 판, 기관 지정 질의만 협약 조항 라벨 등). 표본은 사람이 교차검수 |
| 동결 | 2026-10-25, 분할 해시로 소속을 고정(dev/test 소속 변경 0건). 시험 30%는 최종 판정 전용 |
| 채점 | hit@1/3/5/10, MRR@10, nDCG@10, recall@30·50. **정답을 doc_id 열거가 아니라 «본문 해시 동치류»로** 채점(같은 본문의 다른 판본·사본·형제 문서가 오답으로 깎이는 것을 방지), 이득 상한은 동치 집합 크기까지, 클러스터 단위 부트스트랩(4,000회) |

### 순환 위험·한계

- **라벨 불완전**: v3 교차검수 표본 30건 중 약 **20%가 보정 대상**(단체협약 약 40%, 법령은 낮음). 원인은 같은 본문의 다른 판본·사본·형제 문서가 정답에서 빠진 것이었다. 보정 레코드 18건(교차검수 확정 6 + 단체협약 전수 재계산으로 추가 8 + 주 라벨 교체 2 + 신뢰도 상향 2), 질의 문구 변경 2건. 단체협약 60건 전수 재계산에서 동치 문서가 60 → 78개로 늘고 2건이 강등되어 **정정 레코드가 10/60(약 17%)**이었다.
- **질의가 모델 작성**이라 모델의 어휘 습관이 반영되고, 라벨이 DB 와 «기계 검증»이라는 것은 사람 판단과 같지 않다.
- 질의 독립을 가정하나 같은 기관·같은 항목 질의가 많아 클러스터 상관이 있다(그래서 클러스터 부트스트랩).
- 기준선 요약은 n=40 안팎인 부분이 있어 구간이 넓다.
- 최신 분기 10건은 2026Q3 를 «공개된 것»으로 간주하는 결정을 반영했다(2026Q2 는 legacy).
- 질의 로그는 평가 집합으로 쓰기 위해 설계했으나 개인정보 우려로 한동안 보류했다([10](10_operations.md)).

## 7. 그 밖의 검증

- **변환 A/B**: 같은 PDF 270건으로 파서 두 버전 비교 — PDF 32/150(약 21%) 상이, HWP·HWPX·XLSX 동일. 손실률을 본문 해시 기준으로 정정(16% → 4.2% → 0.8%).
- **검색 지연 실측**: HNSW ef_search 400 에서 recall 0.95~0.98(내규·법령·단체협약), p50 약 1초대.
- **경영평가 종합등급 추출**: 사전등록 기준으로 표본 검수, 외부 발표와 대조한 정정 반영(세부 수치 미수록).
- **A/B 가 못 하는 것**: 사람 평가자는 1명이고 질의는 20건뿐이다. 외부 이용자 만족도·장기 사용 데이터는 아직 없다(미확인).

## 7-2. BM25 전량 시험 — 미통과, 폐기 (2026-11-26)

| 항목 | 내용 |
|---|---|
| 가설 | 키워드 팔을 BM25(PostgreSQL 전문 색인)로 바꾸거나 융합하면 문장형·제목 질의의 hit@1 이 오른다 |
| 1차(E1, 부분집합 약 24만 조문) | 융합 Δhit@1 **+0.11 큰 이득** |
| **전량(E1b, 조문 2,584,317, 내규+단협)** | 이득이 **사라졌다**: 문장형 test(n=79) Δhit@1 +0.000, 키워드형 test(n=214) Δhit@1 +0.009 [−0.033, +0.051], ΔMRR +0.025 [−0.004, +0.054] — 구간이 0 을 포함. 부분집합 +0.25/+0.17 → 전량 +0.06/+0.02. 같은 색인을 부분집합으로 제한하면 부분집합 지표가 소수점까지 재현되어 **구현 차이가 아니라 «방해물이 적은 부분집합 효과»**였다 |
| 원인(육안) | 질의가 «조문 제목만»·«기관명+제목» 템플릿이라 355개 기관의 같은 제목 조문과 같은 기관의 다른 판본이 정답과 동점으로 쏟아진다. 정답 라벨이 1개라는 평가의 구조적 한계 |
| 판정 | 합격 기준 G1(전량 융합 이득) **불충족** → 운영 도입 비권고. 지연·무영향·정확조회 불변은 충족, 단 공시 워밍 지연이 +0.3초 늘었으나 원인은 분리하지 못함 |
| 조치 | 산출 DB 객체(`rag_ext.article_tsv`, 약 2.9GB)는 **삭제**했다(담당 세션 전달 — 삭제 시점 직접 확인은 못 함) |
| 한계 | 질의가 메타 템플릿, 정답 라벨이 문서에서 파생(순환), 사람 검수 라벨 없음, 문장형 분류기 단순, 종단 부하 시험 없음 |

교훈: **부분집합에서의 큰 이득은 전량에서 사라질 수 있다.** 방해물(같은 제목·다른 판본)이 있는 전체 코퍼스에서 먼저 재야 한다.

## 8. 정직한 요약

- 법령 재랭크처럼 **사전 등록을 통과한 개선**은 적용했고, 통과하지 못했거나 불확실한 것(전체 코퍼스 재랭크, 내규 재랭크)은 적용하지 않았다.
- 사례 카드는 사람 눈가림 A/B 에서 유리했지만 **평가자 1명·순환 위험·풀 13%·재현율 약 71%**라서 «표본 기능»으로만 노출한다.
- 시뮬레이션 성공률 46~66%와 인용 오류 약 18%는 개선이 필요한 지점이며, 추정치는 클라이언트 모델에 크게 의존한다.
