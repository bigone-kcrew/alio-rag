# 03. 변환 원리

> 기준일 2026-11-26. 근거: 내부 CONVERTGUIDE·변환 운영 기록·실측 보고서. 워커 주소·하드웨어 등 내부 구성은 일반화했다.

## 1. 개요

원본(hwp·hwpx·pdf·xls·xlsx·docx·pptx)을 **Markdown** 으로 바꾼다. 변환기는 **kordoc**(오픈소스, 한글 문서·PDF·Office → Markdown)이며 스캔 PDF 는 OCR 로 이관한다. 변환 결과는 «본문 + 머리말(frontmatter) + 꼬리 주석(변환 이력)»으로 저장한다.

## 2. 포맷 라우팅

| 확장자 | 파서 |
|---|---|
| hwp · hwpx · hwpml · pdf · xls · xlsx · docx · pptx | **kordoc 단독** |
| doc · ppt(구형) | markitdown 으로 시도, 지원 불가(422)면 영구실패 목록에 누적 |

- pdf 는 markitdown 을 쓰지 않는다(스캔 PDF 에서 멈춘다). pptx 는 kordoc 4.18.3 부터 처리한다(운영에 4.18.2 이하를 올리지 않는다).
- **엔드포인트가 미해결이면 로컬 라이브러리로 조용히 폴백하지 않고 즉시 실패시킨다**(`ROUTING_NO_ENDPOINT`). 버전이 내려앉은 산출물이 정상처럼 쌓이는 것이 최악이기 때문이다.
- 변환기는 응답의 스킴 없는 로컬 이미지 참조(`![image](image_001.png)`)를 제거한다(이미지를 저장하지 않는 텍스트 코퍼스라 깨진 링크가 된다).

## 3. 품질 게이트와 OCR

1. Markdown 이 최소 길이(20자) 미만 → 빈 결과로 본다.
2. PDF 는 페이지당 100자 미만이면 스캔으로 보고 OCR.
3. OCR 대상은 **대기 큐로 미루지 않고 그 자리에서** OCR 엔드포인트로 재시도한다(미루면 md 가 아예 안 남아 코퍼스에서 통째로 빠진다).
4. OCR 도 비면 `ocr_needed` 로 기록하되 재큐 횟수에 상한(기본 2)을 둔다(없으면 기동마다 전량 재시도).
5. `ok:true` 인데 길이가 0~1자인 응답은 «원본에 텍스트가 없는 문서»다. **상태코드만 보지 말고 길이를 확인**한다.
6. 품질 게이트에 걸려 OCR 도 실패했지만 빈약한 텍스트라도 보존한 결과는 `-lowq` 로 표시한다(본문 중앙값 119자 vs 정상 2,536자, 원본은 전부 스캔 PDF).
7. `ocr=true`(자동)는 텍스트 층이 조금이라도 있는 쪽을 건너뛴다. 워터마크·머리글만 있는 스캔 PDF 는 본문이 통째로 빠질 수 있어 강제 모드가 필요한 경우를 따로 가른다.

## 4. GFM 표

표는 **GFM(GitHub Flavored Markdown) 표**로 변환한다. 박스 문자 표나 HTML 표는 청킹·검색·임베딩에서 취급이 나쁘다. 청커는 표 청크마다 1번 청크의 **열 이름 줄(table_header)**을 붙여 열 의미를 보존한다(서빙 단계, [06](06_search_serving.md)). 법령 별표도 같은 원칙이다.

## 5. 변환 매니페스트 — `body_md5`

- 파일 전체 md5 로 변경을 판정하면 무의미하다. md 의 머리말과 꼬리 주석 양쪽에 `converted_at` 이 있어 재변환하면 내용이 같아도 **전건 md5 가 바뀐다**(A/B 에서 손실률을 16% → 4.2% → 0.8% 로 두 번 정정한 원인).
- 그래서 매니페스트의 비교 정본은 `body_md5`(머리말·꼬리 제외 본문 해시)이다. 이 외에 `md5`(전송 손상 검출)·`src_md5`(원본 raw 의 md5)·`parser`·`converted_at`·`original_file` 을 둔다.
- 해시 정의를 두 언어로 옮길 때는 «공백 집합»이 달라 어긋날 수 있으므로 Node 와 대조해야 한다.
- 이 해시는 DB 의 `documents.body_md5`·`src_md5` 로 이어진다([05](05_database.md)).

## 6. 재변환 정책

- 변환기 버전을 올리면 **같은 PDF 의 Markdown 구조가 일부 달라진다**(예: 4.18.3 → 4.18.8 에서 PDF 150건 중 32건, 약 21%가 달라짐, HWP·HWPX·XLSX 는 동일). 그래서 버전 승격 ≠ 자동 전량 재변환이다. 재변환 여부는 A/B 로 판단한다.
- **A/B 는 «raw 대 raw»**로 한다. 저장된 md 와 비교하면 후처리 차이가 «버전 차이»로 보인다. 비교는 `body_md5` 기준이다.
- 재변환은 재적재·재임베딩과 한 묶음이므로, 하기 전에 가드를 둔다(스냅샷, since 리셋, 해시 재사용 판정 등). 같은 md5 의 원본은 한 번만 파싱하고 사본에는 결과를 복사한다.
- 버전이 섞이면 코퍼스가 반씩 다른 파서로 변환된 상태가 된다. 파서 각인(`parser_ver`)은 환경변수 폴백이면 산출물이 거짓말을 하므로 응답에서 읽은 실제 버전을 기록한다.
- 서버 처리 제한(타임아웃)을 넘는 대형 도면·다쪽 스캔 PDF 는 큐 끝으로 보내 별도 러너(쪽 분할)로 처리한다. 이 크기대를 보조 서버에 몰면 CPU 만 태우고 실패만 쌓인다.

## 7. 실패 분류와 영구실패 정책

`FAIL` 하나로 뭉뚱그리면 원본 조건과 우리 쪽 문제가 섞여 파이프라인 결함처럼 보인다. 판정은 로그 문구가 아니라 **원본 시그니처**(매직 바이트 등)로 한다.

| 부류 | 시그니처 | 조치 |
|---|---|---|
| DRM(ONE·SAFER) | 매직 바이트·문서 머리 | 원본 조건, 재시도 무의미 |
| 암호 HWPX | — | 동상 |
| 손상 | 파일 헤더 없음 | 동상 |
| HTML 위장 | 확장자와 다른 내용 | 동상 |
| ZIP_BOMB | 엔트리·크기 한도 초과 | 동상 |
| 타임아웃·연결 끊김 | — | **우리 쪽** — 재시도 대상 |

- **자동 영구실패(2026-10-25 승인)**: 사유가 UNSUPPORTED_FORMAT(DRM·HTML 위장 포함)·CORRUPTED·ENCRYPTED·EMPTY_INPUT·ZIP_BOMB 이면 **1회 실패로 영구실패**(원장 상태 `permanent_fail`)로 편입한다. 일시 유형(통신·시간초과·PARSE_ERROR)은 3회·2일 소진을 유지한다. 재수집(크기·mtime 변경)이면 상태가 초기화되어 다시 시도한다.
- 알림은 «워커 사용 불가»와 «영구 vs 일시 실패율»을 구분한다(영구 유형이 실패율 경고를 오염시키지 않게).
- «처리됨»과 «성공»을 같게 보면 실패가 영구히 제외된다(건너뜀은 재시도되지 않는다). 변환 입력 인덱스는 `abs_raw`(절대 경로)를 우선 쓴다. 한 루트에 상대 경로를 붙이면 다른 트리가 통째로 `skipped_missing` 이 된다.
- 같은 stem 의 `X.hwp` 와 `X.pdf` 가 «같은 `X.md`» 로 가서 서로 덮어쓰는 충돌이 있었다(1,848경로). 경로 규약과 소유 키를 점검한다.
- 개인 기록 유형(예: 본인 이름이 파일명에 있는 건강검진 문서)은 파싱 전에 **색인 제외 규칙**으로 걸러낸다(`src/pipeline/exclude_rules.*`).

## 8. 한계

- 변환 품질은 원본에 달려 있다. 표가 복잡한 PDF 는 구조가 일부 달라지거나 열이 밀릴 수 있다.
- OCR 은 숫자·표 구조에서 오류가 날 수 있다(예: «무혐의»가 «무험의»로 인식된 사례).
- 신규 문서가 적은 날은 변환기의 실전 검증이 되지 않는다(소량 변환만으로는 품질 검증이 부족).
