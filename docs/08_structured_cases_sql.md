# 08. 구조화 조회 · 사례 카드 · `query_sql`

> 기준일 2026-11-26. 근거: `src/serving/structured_query.js`·`structured_expose.js`·`find_cases.js`·`sql_tool.js`·`qlog.js`, `src/extraction/`, DB 구조 조회, 레드팀·검수 보고서(내부). 이 세 도구는 **적재된 표본·추출 결과**를 다루며 공개 서비스에서 가장 오해가 생기기 쉽다. 그래서 한계를 앞에 둔다.

## 0. 세 도구를 이렇게 이해하세요

| 도구 | 무엇을 읽나 | 어떻게 만들어졌나 | 믿을 수 있는 범위 |
|---|---|---|---|
| `structured_query` | 공시 표에서 규칙으로 뽑은 값(`rag_ext`) | **규칙 기반 파서**(결정적) + 검증 열 | 행 조회·건수·기관 1곳 연도별 값. **순위·전 기관 합계·비교는 거부** |
| `find_cases` | LLM 이 공시 문서에서 뽑은 **사례 카드** | **LLM 추출**(요지·결과·원문 인용 위치) | **표본**. 순위·최다·전수 불가, 0건 ≠ 사례 없음 |
| `query_sql` | 공개용 뷰 13개(`rag_sql`) | 위 구조화 표의 공개 투영 | 사용자가 SQL 을 쓰며 서버는 검증·제한·고지만 한다. 적재 표본 기준 |

### 새 데이터셋(b2·c2·contracts)의 응답 정책 — 레드팀 반영

| 허용 | 조건부 | 거부 |
|---|---|---|
| 행 조회, 건수 | 기관 1곳의 연도별 건수·**조건부 총액**(합계행 검증·단위·이상치 통과 시만; 못 하면 행만) | 순위·«최다»·전 기관 합계·상대방 상위 N·기관 간 비교·횟수·비율 통계 |

거부는 `[거부] <이유> — <대안>` 오류로 나가며, 질의 문자열(`q`)에 «순위·최다·횟수·비율·합계·전 기관» 같은 표현이 있어도 거부한다. 이유는 기관마다 공시 형식·단위·누락이 달라 비교가 성립하지 않고, 상대방명 정규화에 한계(대표자·지점명 부착, 개명·계열 미병합, 법인격 다른 업체 병합)가 있기 때문이다.

### 추출과 검증

- **규칙 기반 파서**: 공시 표(Markdown/GFM)를 열 머리글·행 라벨·단위·연도·분기 기준으로 분해(`field_extractor`), 업무추진비·소송·이사회·기부(`b2_extract`), 계약(`contract_parser_v3`), 징계·지적 전용 추출기. 추출기 버전 문자열(`B_VER` 등)을 올리면 전량 재처리된다.
- **검증**: ① 합계행 검증(`sum_check`: 상세 합계 vs 선언 합계, `ok`가 아니면 총액 계산에서 제외·경고) ② 재무 대차대조 항등식(실측 2,028건 중 2,027 일치) ③ 단위 정규화(`unit_std`; 천원·백만원·억원·복합 단위) ④ 합계·소계·집계 행 플래그 ⑤ 같은 (기관·연도) 현행 문서 복수 문제는 «같은 키는 가장 늦은 제출 문서 행만» 으로 뷰 재정의 ⑥ 파싱 플래그(`parse_flags`)를 공개 뷰에서 품질 표식(`coverage_warn`·`multi_doc_round`·`amount_missing` 등)으로 노출.
- **레드팀(2026-11-23)이 찾은 필수 수정 6건**(요약): 계약 금액 단위 배수 오판 잔존, 같은 (기관·연도)에 현행 문서 복수(179그룹), 합계·소계 행이 일반 행, 상대방 순위 상위가 개인·빈 문자열, 공동수급 caveat 오기, 앱 DB 역할이 superuser 이고 트랜잭션이 READ ONLY 가 아님. 데이터 층 조치와 뷰 재정의, `READ ONLY` 강제, 오류 메시지 일반화로 보정했다. 레드팀은 **계약(`contracts`)을 보정이 끝나기 전까지 끄라고 권고**했다. 2026-11-26 `tools/list` 에서는 `contracts` 가 노출되어 있다(열기까지의 판정 경위는 이 저장소 자료에서 확인하지 못함 — 미확인).
- **단위 오표기 수정(2026-11-26)**: 일부 `doc_fields` 값의 단위 오표기를 원천 UPDATE·추출기 패치·뷰 보정으로 고쳤다(롤백 경로 보존).
- **경영평가 종합등급**: 문서에서 규칙으로 뽑은 종합등급 표(`c2_eval_overall`)를 사전등록한 기준으로 표본 검수했고, 공식 발표와 대조한 정정 표식(`verified_state` 의 `superseded_…`)을 뷰에 반영했다. 충돌 행은 뷰에서 제외하며, 지표별 등급 고지를 동반한다(세부 검수 수치는 미수록).
- 알려진 한계: 임원(20305) 성명 열거는 정책 결정 사항, 복합 단위 약 16만 행의 `unit_std` 미정, `staff_total` 은 정원이며 현원 총계 키가 없다, `field='avg_pay'` 부분일치가 성별·무기계약 행까지 반환할 수 있다.

## 2. 사례 카드 (`find_cases`)

### 무엇인가
공시 문서(이사회 회의록 43005, 감사결과 43006, 노사협의회 회의록 21028, 단체협약 63795, 노사합의·임금협약 63796 등)에서 **LLM 이 사례를 뽑아** 만든 카드. 각 카드는 `summary`(모델 요약), `result`(결과 문구), `quote`(**원문 인용, 원문 그대로**)와 그 **위치**(`quote_start/end`), `case_type`, `topics`, `favor`(favorable/neutral/unfavorable/unknown, **모델 의견**), `confidence` 를 가진다. 근거 법령은 인용문에서 정규식+법령명 사전으로 자동 연결(`legal_basis`).

### 어떻게 만들었나
1. 대상 문서 선별(최근 12개월 제출분 중 코드별 풀 약 3,000문서, 코드·기간별 확대는 사람 승인).
2. LLM(EXAONE 계열) 추출 — 문서 발췌를 모델에 보내 JSON 카드를 받는다. 모델·프롬프트 버전·실행(run) 단위로 기록한다(`card_runs`, `model`, `prompt_ver`). 외부 LLM API 를 사용했으므로 문서 발췌가 API 로 전송되었다(이용 조건·승인 범위는 [NOTICE](../NOTICE.md)의 확인 사항).
3. **후처리**: 결과 정규화(`result_norm`·`result_list`), 절차적 안건(`is_procedural`)·부결 의심(`bugyeol_suspect`)·범위 이탈(`scope_flag`) 표식, 재게시 판정(`is_repost`)·동일 사건 묶음(`dup_group`, `card_event`)·기관 불일치(`inst_mismatch`), 개인정보 마스킹(`quote_masked`), 품질 등급(`quality`).
4. `quote_match`: **인용문이 원문에 실제로 있는지**를 위치로 검증한다.
5. 노출은 코드 단위로 승인한다. 현재 노출: 이사회 43005, 감사결과 43006, 노사협의회 21028(21028 은 `favor` 표시 없음). **보류**: 63795·63796(재게시 59%·45%), 감사원 지적·경영평가(전량 추출 후), 국회 지적.

- **필요성 측정(2026-11-26 레드팀, 골든 30 중 gold 있는 25질의, 검색 재현율만)**: 카드 `find_cases` P@10 0.841·recall@20 0.818 vs 카드 없는 일반 검색 P@10 0.2 안팎. 단 이 우열은 **부풀려져 있다** — 정답(gold)이 카드 술어로 정의되어 순환적이고, 일반 검색 결과의 64%가 카드 풀 밖이라 «놓침»으로 계산되었다(풀 안만 보면 일반 검색 정밀도 0.46~0.56). 카드가 답변 품질을 높인다는 입증은 사람 A/B 한 건뿐이다.
- **결론(레드팀)**: 판정 «축소» — 현재 노출 3코드와 현 추출분은 유지, 신규 코드 확대와 재추출 증식은 독립 검증 통과 전까지 동결.
- 비용·유지: 추출에 EXAONE 계산 수십 시간, 관련 코드 약 1.2만 줄, 도구 목록 크기 +약 7%, env 플래그 10종 이상.
- `find_cases` 규칙: READ ONLY, 값 바인딩, **정규식 비허용**(키워드는 이스케이프한 LIKE), `limit`≤30, 동시 2건, 분당 한도, 5초 타임아웃, 순위·최다·집계 요구 거부, 응답 문자열 마스킹.

## 3. `query_sql` 정책 계층

사용자(클라이언트 LLM)가 SQL 을 쓰고, 서버는 **검증·제한·고지**만 한다(서버 LLM 호출 0건). 겹겹의 방어다.

1. **토큰 검증기**: SELECT/WITH 한 문장만, 다중 문·주석(`--`, `/* */`)·달러 인용·`E/U&/B/X` 접두 문자열·문자열 안 역슬래시 거부, 길이 6,000자 이하, `WITH RECURSIVE` 거부, DML/DDL/`SET`/`COPY`/`EXPLAIN`/`INTO`/`FOR UPDATE` 등 키워드 거부, **함수 허용 목록**(집계·문자열·날짜·창 함수 기본형만), FROM 절 표 반환 함수 거부, `pg_` 접두·`information_schema`·시스템 카탈로그 거부, 형 변환은 일부 타입만, **관계 허용 목록**(뷰 이름만, 스키마 한정자 거부).
2. **전용 DB 롤**: `mcp_sql_ro`는 `rag_sql` 의 13개 뷰에만 SELECT 권한이 있다([05](05_database.md)).
3. **READ ONLY 트랜잭션** + `statement_timeout`(기본 5초) + `search_path` 고정.
4. **EXPLAIN 비용 상한**(기본 3,000,000 — 거대 조인 사전 차단): 초과는 실행하지 않고 거부.
5. **행·셀·응답 상한**: 기본 200행(최대 1,000), 응답 60,000바이트.
6. **동시·분당 한도**: 기본 동시 2, 분당 30.
7. **정책 고지(policy)**:
   - 항상 `coverage` 고지(적재 표본 기준).
   - **합계 질의 강제**: `SUM` 이 있고 업무추진비·기부·출연 표인데 `sum_check` 를 언급하지 않으면 **거부**(합계행 검증 열을 함께 쓰라고 안내).
   - 전 기관 집계에는 scope 경고, `sum_check≠ok` 행 경고, 유사 기관명 `LIKE` 경고, 0건일 때 `zero_hint`(값을 지어내지 말고 «확인할 수 없음»으로 답하거나 기관명을 정식명으로 다시 시도).
   - 계약 뷰(활성화 시)는 금액 합·평균에 `amount_flag` 조건을 요구(off/warn/reject 설정).
8. **등급별 허용 뷰**: internal 은 13개 전부, **external 은 자유 서술 열이 있는 이사회(`b2_board`·`c2_board_*`)·지적(`c2_finding_item`) 표를 제외**한다(기본 허용 목록; 운영 설정으로 바뀔 수 있음 — 미확인).
9. **감사 로그(`SQL_TOOL_AUDIT=on`)**: 정규화한 SQL(리터럴·주석·인용 식별자·달러 인용을 자리표시자로 치환) + 해시 + 참조 뷰 + 바인딩 개수 + 행 수 + 정책 경고 코드 + 거부 코드 + 소요 ms. **바인딩 값·리터럴·결과 셀·키·IP 는 기록하지 않는다.** 닫히지 않은 따옴표·주석은 끝까지 버려 내용 누출을 막는다.
10. **가이드**: `list_catalog(kind=sql_guide)` 가 뷰별 열 설명·예시·규칙을 담은 마크다운 가이드를 돌려준다(생성기 산출 JSON 의 구조: `version`·`generated_at`·`header_md`·`footer_md`·`tables[{name,tier,md,examples}]`. 이 저장소에는 데이터 파일을 넣지 않았다). 가이드 v2 는 2026-11-26 적용.

### 설계 선택의 근거
외부 «자동 온톨로지» 방식과 비교한 3자 시험(51문항)에서 자체 text-to-SQL 방식(B)이 90%, 다른 방식이 60~64% 였다. 그래서 **서버가 질의를 해석하지 않고 클라이언트 LLM 이 SQL 을 쓰되 서버는 안전만 책임지는** 구조로 갔다. 이 시험의 상세 데이터는 공개하지 않는다.

### 사용 규칙
- 먼저 `list_catalog(kind=sql_guide)`.
- 값은 `$1..` 로 바인딩. 기관은 `rag_sql.institutions` 로 코드를 먼저 찾는다.
- 합계는 `sum_check = 'ok'` 와 함께.
- «전체·최다·순위» 결론을 내지 않는다. 0건은 «확인되지 않음».
