# 04. 적재와 임베딩

> 기준일 2026-11-26. 근거: `src/pipeline/` 코드(서버 파이프라인 컨테이너에서 복사), `pg_indexes`·`load_runs` 조회, 운영 기록. 수치는 조회일 기준이다.

## 1. 문서 → 조문(청크) 파싱

두 개의 파서가 같은 «스테이징 JSONL» 형식(문서 레코드 + 조문 레코드)을 만든다.

| 파서 | 대상 | 방식 |
|---|---|---|
| `parse_articles.js` | 법령·기관 내규·단체협약 | Markdown 을 **조(제N조 / 제N조의M)** 단위로 분해. 장(chapter)·구분(본칙/부칙/별표)·조 번호(art_no, art_sub)·제목·본문을 남긴다. 조문이 없는 단체협약은 문단 누적 청커로 폴백한다 |
| `parse_disclosure.js` | 경영공시(비조문형) | 문서를 검색용 **청크**로 분해(조 번호 없음, `section='본칙'`, `art_no=null`). 표는 행 단위로 묶는다 |

- 증분 옵션 `--since`(mtime 이후 파일만)와 `--out`(출력 디렉터리)을 **같이** 쓴다. `--since` 만 주고 `--out` 을 빼면 전체 스테이징이 델타로 축소되고, 그 상태로 전량 재적재하면 나머지 문서가 사라진다.
- 문서 레코드에는 `parse_status`(`chunked`·`ok`·`low_coverage`·`no_articles`·`truncated`·`empty`·`shell_no_body`), 커버리지(`covered_chars/content_chars`)가 남는다. 변환 이력(`parser_ver`·`converted_at`·`ocr_kind`·`body_md5`·`src_md5`·`origin`)은 내부 감사용이며 응답·임베딩·해시에 쓰이지 않는다.
- 색인 제외 규칙(`exclude_rules`)은 문서를 만들기 **전에** 걸러낸다(개인 기록 유형). 규칙을 늘려도 이미 적재된 문서는 자동으로 지워지지 않는다(수동 삭제).
- 재게시 별칭: 같은 기관·항목·하위경로의 다른 회차 재게시는 대표(최근 회차)만 색인하고, 별칭 경로는 대표 문서의 `meta.aliases` 에 남기는 옵션(`DUP_MAP`)이 있다. 기본 정책은 전량 색인이고 이 옵션은 지도 파일이 있을 때만 동작한다.

## 2. 청킹

규칙 세트 식별자 `RULESET = chunk-v4-cut3500-abs3200+ca-fallback-A+gfm` 를 청커 파일 세 곳이 공유하며 `load_runs.embed_spec` 에 기록한다. **청킹·파싱 규칙을 바꾸면 이 값을 함께 올려야 하고, 그러면 해시가 바뀐다(= 재임베딩).**

| 상수 | 값 | 뜻 |
|---|---|---|
| 청크 목표 | 내용 길이 ÷ 40 (적응형), 상한 2,500자 | 과대 청크는 임베딩 의미를 희석시킨다 |
| 문서당 최대 청크 | 2,000 | 거대 OCR 덤프 방어 |
| 최소 청크 | 40자 | 더 짧은 조각은 버리지 않고 직전 청크에 흡수(글자·숫자가 하나도 없는 조각만 버림) |
| 오버랩 | 120자 | 문단 누적 청커 |
| 흡수 한도 | 3,200자 (= 임베딩 컷 3,500 − 접두 여유 300) | 접두·제목이 앞에 붙은 뒤 잘리므로 꼬리 유실을 막는다 |

- HTML 잡음 제거는 **청크 산정 전**에 한다(변환기 꼬리 주석 유무가 청크 크기와 해시를 바꾸지 않게). 알려진 HTML 태그만 지우고 `<MBC>`·`<137>`·`<개정 2020.1.1>` 같은 본문 꺾쇠는 보존한다. 엔티티는 태그 제거 뒤에 푼다.
- 표 청크는 GFM 표를 행 단위로 유지한다. 중첩 표에서 안쪽 표 뒤 바깥 셀 본문이 버려지던 결함이 있었고 수정되었다.

## 3. 조문 앵커 `art_key`

`articles.id`(행 번호)는 재적재마다 바뀌므로 외부 연결(인용 링크, 북마크, 평가셋)의 키는 **`(doc_id, art_key)`** 다. 규칙은 결정적이다.

- 조문 문서: `제N조` / `제N조의M`, 번호가 없으면 `t:<정규화 제목>`(NFC, 공백 압축, 최대 80자), 둘 다 없으면 `@<seq>`. 부칙은 앞에 `부칙/`. 중복은 `#2`, `#3`.
- 문서 수준 앵커(`anchor_level='document'`): 공시 청크와 청커로 만든 문서는 전부 `@<seq>` — 청커 규칙·본문이 바뀌면 순번이 움직이므로 «문서 수준(doc_id + body_md5)만» 쓰라는 표시다.

## 4. 적재 (`load_pg.js`)

| 모드 | 동작 | 용도 |
|---|---|---|
| `full` | 코퍼스(legal·bylaws·ca) `TRUNCATE` 후 재적재 | 전면 재구축. **고유 해시 수 사전 산정값(`EXPECT_UNIQUE`) 필수** |
| `append` | 공시(disclosure) 추가 적재 | 공시는 full 이 넣지 않고 별도 |
| `delta` | **문서 단위 교체**: 대상 `doc_id` 의 `articles` 를 지우고 다시 넣는다(트랜잭션) | 일일 증분 |

- 적재 전 **게이트**(`load_gate.js`, DB 접근 없음): 코퍼스별 문서 수·청크 0개·잘림·낮은 커버리지 비율을 보고하고 거부 로그(TSV)를 남긴다. 고유 해시 수가 사전 산정값의 ±5% 안인지, 이전 적재와 같은 «해시 정의»(컷·접두·청커·차원)인지 확인한다. 한 DB 에 두 정의가 섞이지 않게 하는 장치다.
- `delta` 에서는 `EXPECT_UNIQUE` 를 쓸 수 없다(DB 전역 `embed_queue` 건수와 비교하는 검사라 변경분에는 의미가 없다).
- 감사 컬럼: `created_at/by`, `updated_at/by`, `load_run_id`. 실행 이력은 `load_runs`(`script`, `mode`, `corpus`, 시작·종료, 문서·조문 수, `code_rev`, `embed_spec`)에 남는다. 종료 시각이 NULL 인 행은 실패·롤백한 실행의 흔적으로 설계상 정상이며(INSERT 가 트랜잭션 밖), 임베딩 규격 판정은 `finished_at IS NOT NULL` 인 가장 최근 행만 쓴다.
- 조회 시점 2026-11-26: `load_runs` 87행(`delta` 82 · `full` 3 · `append` 2).
- 적재 스크립트가 `TRUNCATE` 하면 `documents.alias`(법령 약칭)·`usecases`(활용처 태그)가 비므로 `backfill_law_alias.js`·`backfill_usecase.js` 를 다시 돌린다. `article_embeddings` 에는 FK 가 없어 벡터는 보존된다(그래서 고아가 남는다).

## 5. 임베딩

| 항목 | 값 |
|---|---|
| 모델 | **bge-m3** (BAAI/bge-m3, 다국어, 1024차원 네이티브) |
| 서빙 | 현행: 로컬 GPU 의 ollama(질의 임베딩도 같은 모델). 전량 임베딩 시기에는 유료 API(OpenRouter `baai/bge-m3`)를 쓰기도 했다(비용 누적·예산 가드가 클라이언트에 있다) |
| 입력 | `alio_embed_text()` SQL 함수가 정의: (접두) + 제목 + 본문을 **3,500자(코드포인트)** 에서 자른다 |
| 접두 | `[기관명] 문서명 > 장 > 구분 \| 개념` — 정책 `unique-only+always:ca`: 기본은 «본문이 전역에서 유일할 때만» 붙이고(본문이 같은 청크가 여러 곳에 있으면 접두 없는 공통 해시로 벡터를 공유), `ca`(단체협약)는 항상 붙인다. 접두 여부는 `article_hash.prefixed`·`base_hash` 에 저장되어 임베딩 단계가 같은 판정을 재현할 필요가 없다. 새 중복이 생기면 기존 접두 행의 접두를 떼고 구 벡터는 고아가 된다 |
| 해시 | `text_hash` = 임베딩 입력의 해시. **본문이 같은 청크는 같은 해시를 공유**하고 벡터를 1개만 만든다 |

- **입력 정의는 `embed_spec.js` 한 곳에만 둔다.** 컷·접두·모델·차원 중 무엇이든 바꾸면 `text_hash` 가 전부 바뀐다 = 전량 재임베딩 + HNSW 재빌드이기 때문이다. `load_pg.js`(SQL 함수), `embed_articles.js`(최대 길이 단언), `_create_hnsw.js`, 검색 SQL 이 모두 여기를 읽는다.
- 모델 라벨이 두 종류(`baai/bge-m3`, `bge-m3`)인 것은 서빙 경로별 표기 차이다. `ALLOWED_MODELS` 에 둘 다 허용된다.
- `embed_client.js`: 재시도(지수 백오프, 429·5xx·네트워크), **차원 단언**(1024 아니면 실패), 응답 usage 에서 비용 누적, 예산 가드 도달 시 새 배치를 투입하지 않고 종료(rc=3), 상태 파일은 «응답 직후·DB 쓰기 전»에 원자적으로 저장.
- 체크포인트는 DB 자체다. `article_embeddings` 에 있는 해시는 건너뛴다(재개 = 재실행, 멱등).
- 개인정보는 **적재 시점에 청크 텍스트에서 마스킹**하므로 임베딩 입력에 원문이 들어가지 않는다([10](10_operations.md)).

### 모델 선택 근거 (기록)

초기에는 NVIDIA NIM 의 임베딩 모델을 썼다(계정에서 호출 가능한 모델을 전수 시험해 한국어 구분력이 있는 유일한 모델을 선택). 이후 2026-10 에 bge-m3 로 전환했다. 일상어 질의로 시험했을 때 키워드가 없는 질문도 맞는 조문을 찾는지를 기준으로 삼았고, 전환 후 전량 재임베딩했다. 이 절의 수치(속도·가격)는 당시 시험값이라 현재와 다를 수 있다.

## 6. 인덱스 (HNSW, 부분 인덱스)

저장은 `vector(1024)` 전정밀도이고, 인덱스는 **표현식 인덱스**다. 코퍼스별 부분 인덱스(`WHERE corpora @> ARRAY[...]`) 5개가 있다(2026-11-26 `pg_indexes` 조회).

| 인덱스 | 대상 | 방식 | 파라미터 |
|---|---|---|---|
| `idx_emb_hnsw_legal` | 법령 | `halfvec(1024)` 코사인 | m=24, ef_construction=128 |
| `idx_emb_hnsw_bylaws` | 기관 내규 | 동상 | m=24, ef_construction=128 |
| `idx_emb_hnsw_bylaws_extra` | 출연연 내규 | 동상 | m=24, ef_construction=128 |
| `idx_emb_hnsw_ca` | 단체협약 | 동상 | m=24, ef_construction=128 |
| `idx_emb_hnsw_disclosure` | 경영공시 | **이진 양자화 `bit(1024)` 해밍** | m=16, ef_construction=64 |

- 질의는 «인덱스로 후보 N개 → 원본 vector 로 정확 재순위» 순서다. 공시는 후보 수(비트 후보 약 4,000)가 크므로 반복 스캔(`iterative_scan=relaxed_order`)으로 채운다. 세션 설정 기본 `hnsw.ef_search=400`(스테이징 실측: 1000 은 차가운 캐시에서 15초 제한에 걸렸고 400 은 p50 약 1.06초·실패 0).
- 경영공시(가장 큰 코퍼스)에는 정밀도를 일부 포기하고 비트 양자화를 썼다. «품질을 양자화로 깎지 않는다»는 방침과 상충하지 않도록 재검색(원본 재순위)을 둔다.
- **재임베딩 순서(대량)**: `load_pg(full)` → `append disclosure` → 약칭·활용처 백필 → **HNSW 내리기(`_drop_hnsw`)** → 임베딩 → **고아 정리(`_cleanup_orphans`)** → HNSW 만들기(`_create_hnsw`) → 활용처 kNN 태깅. 인덱스를 붙인 채 임베딩하면 17.5배 느렸다(시간당 23,878건 → 370,326건). 고아 정리를 빼면 유효하지 않은 벡터(재변환 뒤 본문 해시가 바뀐 구 벡터, 한때 전체의 34.8%)를 인덱싱한다.
- HNSW 빌드는 컨테이너 공유 메모리 제약으로 병렬 워커를 쓸 수 없는 환경이 있었다(직렬 빌드 필수). 재생성에는 며칠이 걸릴 수 있다(한 차례 48.9시간 기록).

## 7. 일일 델타 체인 (새벽 04:35)

```mermaid
flowchart LR
  A["어제 04:35 이후<br/>바뀐 md 선별(mtime)"] --> B["스테이징 분리 디렉터리에<br/>parse_articles / parse_disclosure"]
  B --> C["load_pg --delta<br/>문서 단위 교체(트랜잭션)"]
  C --> D["신규 text_hash 만 임베딩"]
  D --> E["상태 파일 갱신<br/>(실패 시 갱신 안 함)"]
```

- 범위: 어제 새벽 이후 바뀐 공시 md(+내규·법령·협약의 변경분). **상태 파일은 실패하면 갱신되지 않아** 다음 실행이 같은 델타를 다시 잡는다.
- 하지 않는 것: TRUNCATE 경로, HNSW 내리기, 전체 스테이징 수정, 변환기 가동 중 실행(rc=75).
- 상한: 델타 문서 수가 20,000 을 넘으면 사람에게 넘기고 멈춘다(복사·재변환으로 mtime 이 대량 갱신된 날 방지). 파일을 옮길 때는 mtime 을 보존해야 한다.
- 임베딩은 GPU 서버 샤드로 병렬 처리한다. 가용 메모리가 낮으면 임베딩만 이월하고 다음 실행이 이어받는다. 신규 벡터는 인덱스를 붙인 채 적재한다(증분은 소량이라 허용, 실측 약 24k 벡터/시간).
- 새벽 델타 결과는 데드맨 점검(06:50)이 확인한다([10](10_operations.md)).

## 8. 법령 판본·연혁 처리

- 법령 문서마다 `edition_group`, `edition_status`(`current`·`superseded`·`scheduled`·`repealed`·`lineage_closed`), `effective_from/to`, `repealed`, `lineage_successor` 를 둔다(`documents.meta` 와 파생 열).
- 기본 검색은 **현행판만** 노출한다. 과거 판은 `all_versions=true`, 특정 시점은 `as_of`. 내규도 같은 규칙이다([06](06_search_serving.md)).
- **내규-법령 정합**: 내규가 인용하는 법령의 개정 시점과 내규 개정 시점의 격차를 계산해 `bylaw_law_compliance` 에 남긴다(일일 갱신, 약 2.5분, 자기 테이블 교체). 판정 flags 에 상한을 두면 롱테일 법령이 통째로 사라지므로 상한은 커버리지가 아니라 상한임을 알고 쓴다(과거 60.4%가 버려진 사례).
- **내규 인용 링크**: `rag_ext.bylaw_cite_link`(509,854행, 2026-11-26 13:56 재적재)가 내규·단체협약 조문 본문의 «법령명 + 제N조» 인용을 규칙으로 추출해 대상 법령·판본에 연결해 보관한다. `find_citing`(법령 역조회)의 기반이며, `get_related` 는 질의 시점에 본문에서 정규식으로 인용을 뽑는 별도 경로다. 구조·정밀도·한계는 [05](05_database.md)·[08](08_structured_cases_sql.md). 일일 델타 편입은 «제안 단계(미구현)»라서 새 내규가 들어와도 이 표는 수동 재적재 전까지 갱신되지 않는다.

## 9. 정합성 검사

- **파일 ↔ DB 양방향 대조**: md 매니페스트(`body_md5`)와 `documents.body_md5` 를 비교해 «있어야 하는데 없는 문서», «DB 에만 있는 문서»를 찾는다. 고아 md(원본이 없는 md)를 곧바로 지우지 않는다(이관·회차 폴더 이동의 부산물일 수 있다).
- **임베딩 직전 raw·md 개수 기록**: 한 번의 단계가 끝날 때마다 raw·md·청크·고유 해시 수를 남겨 이후 증감을 설명할 수 있게 한다.
- **유효 벡터 = `article_hash` 와 조인되는 것만 센다.** `article_embeddings` 전체 행 수는 고아를 포함하므로 규모 표기에 쓰지 않는다(README 의 공식 집계 정의 참조).
- 임베딩 대기 0 확인: `embed_queue` 와 `article_embeddings` 의 해시 차집합이 0 인지 본다.
- 한계: 같은 stem 의 서로 다른 원본(`X.hwp`/`X.pdf`)이 한 md 경로를 공유하는 충돌, 첨부 단위 구멍 등은 일반 대조로 안 보여 별도 점검을 돌린다([11](11_lessons_pitfalls.md)).
