# 11. 함정과 교훈

> 기준일 2026-11-26. 내부 함정 기록(약 100항목)과 작업 메모를 주제별로 추려 일반화했다. 개인정보·비밀값·내부 구성은 제외했다. «🔴»로 표시한 것은 비용이 컸거나 반복된 것이다.

## A. 착수 전

- 🔴 **과거 기록을 읽지 않고 손대면 같은 사고를 반복한다.** 작업 전 해당 영역의 기록·결정 이력을 먼저 읽는다.
- 🔴 **«조회»인 줄 알았는데 정본을 쓰는 명령**이 있다(캐시·상태 파일·체크포인트 갱신). 읽기 전용이라고 믿기 전에 스크립트를 읽는다.
- 🔴 **인자 없이 부른 빌더가 저장소 전체를 훑는다.** 기본값이 넓은 스크립트는 범위를 명시한다.
- 🔴 `.env` 류·`env | grep` 출력에 비밀값이 섞였다(하루 세 번). 값 마스킹은 «키 이름만 보는 명령»으로 한다.

## B. 세는 법·판정

- 🔴 **표본으로 전수를 판정하지 않는다.** «누락 N건»은 항상 상한이다.
- 🔴 **산출물이 없는 것을 0 으로 읽지 않는다.** «측정 실패»와 «측정값 0»을 구분한다(없는 사고를 만든다).
- 🔴 실패 로그로 분모를 세지 않는다. 옛 경로를 재고 «정상»이라 하지 않는다.
- 🔴 **정상 기준선 없이 «이상»이라 판정하지 않는다.**
- 마이크로벤치·초기 표본이 오도한다(단발 측정으로 가중치를 뒤집지 않는다).
- 🔴 **항목 코드와 폴더 코드가 다르다.** 경로 차집합은 «누락»이 아니다(회차 폴더를 먼저 접는다).
- 🔴 **재변환이 조용히 건너뛴다.** 판정은 파서 각인 수로 한다. 체크포인트는 «파일이 있다»를 보증하지 않는다.
- 🔴 **«같은 설정»의 기본값이 파일마다 다르다.** 쓰이는 범위를 확인하고 말한다.
- 감사 집계는 «문서(id)» 단위로 센다(스트림 체크포인트 항목 수는 부풀고, 하드코딩 태그 목록은 누락을 만든다).
- 경계 값으로 스트림을 나눌 때 `MAX=N / MIN=N+0.001` 은 틈을 만든다.

## C. 운영·프로세스

- 🔴 **돌고 있는 파이프라인을 고치는 행위가 사고를 만든다**(셸 스크립트 제자리 수정 → 끝부분 문법 오류).
- 🔴 `pkill -f` 가 내 셸을 죽인다. 컨테이너 안 `bash -c "… grep … kill …"` 이 자기 자신을 죽인다.
- 🔴 **감시·재분배 장치가 조용히 죽는다.** 좀비는 «살아있는 것»처럼 보인다(`kill -0` 단독 금지).
- 🔴 `--rm` 컨테이너는 `docker stop` 이 지운다. 호스트 패키지 업그레이드가 데몬을 재시작하면 컨테이너 안 포워드가 사라진다.
- 🔴 클라이언트를 죽여도 서버 작업은 계속 돈다. 공유 서버(변환기)에 크래시 재현 시험을 직접 보내면 운영 도구가 끊긴다.
- 🔴 **실패를 로그만 찍고 다음 단계로 넘어가면 «완료»가 거짓이 된다.**
- 🔴 로그 한 줄이 수집을 죽였다(알리려던 것이 잃는 것이 됨). 알림 실패는 본 작업을 막지 않는다.
- 🔴 샤드 N개가 한 체크포인트 파일을 공유하면 서로의 기록을 지운다.
- 🔴 **고친 것이 형제 구현으로 전파되지 않는다.** 같은 결함을 세 번 고쳤는데 네 번째가 남았다 → 형제 구현을 먼저 찾는다.
- 🔴 «처리됨»과 «성공»을 같게 보지 않는다(실패가 영구히 제외된다).
- 성공을 확인하지 않고 원본을 지우면 실패한 순간 일감이 증발한다.
- 오래 걸리는 외부 호출(예: 요청 상한 300초 기본값)은 클라이언트 설정이 서버 제한과 다를 수 있다.
- 서브에이전트가 취약 호스트에서 전수 스캔(`find /`)을 돌려 I/O 를 소모했다 → 범위·부하 제한을 지시에 명시한다.

## D. 수집

- 🔴 **폴더 키가 날짜면 같은 날 두 번 올라온 공시가 서로를 덮어쓴다.** 회차 구분 경로를 쓴다.
- 🔴 분기가 비어 수집된 공시는 평문 `<연도>` 로 남는다. 격리 이동은 디스크 경계를 넘는다.
- 🔴 보유 판정이 낡은 인덱스면 있는 공시를 누락으로 센다.
- 🔴 점검할 때마다 «누락»이 뜨는 구조적 원인이 다섯 가지였다(점검 도구 정의가 달랐음).
- 🔴 폐기한 수집기가 맡던 서식을 새 경로가 안 덮으면 증분이 조용히 비어 있다.
- 🔴 중첩 zip: 바깥을 처리하다 안쪽이 먼저 격리된다. 한글 파일명(cp949) 깨짐.
- 🔴 이관은 게시판형에서 반복해서 샌다.
- 🔴 증분 점검에서 캐시가 만료된 큰 기관의 «전체 목록 재조회»가 레인을 몇 시간 붙잡는다.
- 요청 예산: 차단은 평균률이 아니라 **통제 밖 수집기의 버스트**가 불렀다. 모든 수집기가 같은 관문을 지난다.
- 목록 절단 오류는 전수 열거가 끝난 기관에서는 누락이 아니다.

## E. 변환

- 🔴 **변환 전후 비교는 꼬리 주석·머리말을 뗀 본문끼리** 한다(같은 착시를 세 번 밟았다). 파서 A/B 는 raw 대 raw.
- 🔴 `X.hwp` 와 `X.pdf` 가 같은 `X.md` 로 가서 서로 덮어쓴다.
- 🔴 변환기 꼬리 주석이 청크 해시·크기·«짧은 꼬리 보존»을 떠받치고 있었다. 주석만 지우면 임베딩 입력과 내용이 어긋난다.
- 🔴 청커의 태그 제거 정규식이 본문의 꺾쇠(`<MBC>`·`<137>`·`<개정 …>`)를 같이 지웠다. 알려진 태그만 지운다.
- 🔴 공시 청커가 중첩 표의 안쪽 표 뒤 바깥 셀 본문을 버렸다.
- 🔴 버전 각인이 환경변수 폴백이면 산출물이 거짓말을 한다. 응답에서 읽은 실제 버전을 기록한다.
- 🔴 실패 응답의 `code` 를 버리면 «HTTP 200 실패»라는 모순이 남는다.
- 🔴 서버 처리 제한(타임아웃)은 대형 도면·다쪽 스캔 PDF 에서 «조용한 누락»이 된다. 큐 끝으로 보낸다.
- 🔴 `ocr=true`(자동)는 텍스트 층이 조금이라도 있는 쪽을 건너뛴다(워터마크만 있는 스캔 PDF).
- 🔴 실패한 문서는 해시 재사용이 안 된다 — 같은 내용의 중복 첨부 N건이 각각 서버 제한 시간을 태운다.
- 같은 서비스 N대의 CPU 쿼터가 비대칭이면 LB 평균이 느린 쪽으로 간다. OCR 처리량은 인스턴스 늘리기로 늘지 않는다.
- 해시 정의를 두 언어로 옮길 때 «공백 집합»이 다르다.
- js-yaml 은 값이 undefined 인 키를 조용히 건너뛴다(머리말 버그).
- `UNSUPPORTED_FORMAT` 대부분은 DRM 이다(매직 바이트로 가른다).

## F. 적재·임베딩·DB

- 🔴 **대량 재임베딩은 HNSW 를 내리고 고아를 지운 뒤에** — 순서를 어기면 17.5배 느려지고 유효하지 않은 벡터를 헛인덱싱한다.
- 🔴 `load_pg` 기본(full)은 일부 코퍼스만 넣는다. 공시는 별도 `--append`. 단독 호출하지 말고 정본 체인을 쓴다.
- 🔴 TRUNCATE 는 벡터를 남긴다(FK 없음) → 고아. `documents.alias`·`usecases` 가 비므로 백필 재실행.
- 🔴 **임베딩 입력 정의(컷·접두·모델·차원)를 바꾸면 전량 재임베딩.** 한 파일에서만 정의한다.
- 🔴 `--since` 만 주고 `--out` 을 안 주면 전체 스테이징이 델타로 축소된다.
- 🔴 법령정합 flags 에 상한을 두면 롱테일이 통째로 사라진다(상한은 커버리지가 아니다).
- 🔴 pg_bigm 은 `ILIKE` 로는 인덱스를 못 탄다(`lower() LIKE` 식 일치 필수).
- 🔴 HNSW + 필터는 선택적 필터에서 느리다 → 후보 선축소 2단계.
- 🔴 `load_runs` 의 종료 시각 NULL 행은 실패 흔적으로 정상(닫으면 규격 판정이 오염).
- 🔴 같은 stem 충돌, 비소유 키(한 md 경로를 여러 원본이 공유) 문제.
- 델타는 doc_id 범위 교체라 총계가 단조 증가가 아니다. 수치는 하드코딩하지 않는다.
- 규모를 말할 때 `reltuples`(추정치)나 고아 포함 행 수를 쓰지 않는다.

## G. 검색·서빙

- 🔴 **효과가 불확실한 순위 변경은 플래그 off 로 두고 측정한다**(사전 등록, test 1회).
- 🔴 `period_label`(제출 회차)과 보고 대상 기간은 다르다. 섞으면 조용히 틀린다.
- 🔴 `series_latest=false` 는 «이 행이 틀렸다»가 아니다.
- 🔴 «현행판만»이 기본이므로 연혁이 필요한 질문은 `as_of`/`all_versions` 를 쓴다.
- 🔴 카테고리 필터를 HNSW 질의 SQL 에 그대로 얹으면 인덱스를 버려 전량 타임아웃.
- 🔴 «찾지 못함 ≠ 없음». 0건 응답에 사유와 한계를 싣는다.
- 🔴 **순위·최다·합계 질문은 상위 k 검색으로 답할 수 없다**(도구가 거부·고지).
- 🔴 사례 카드의 우열은 순환 정의·풀 밖 계산으로 부풀려질 수 있다 — 평가 설계를 의심한다.
- 컨테이너 파일 쓰기가 막힌 환경에서는 `docker cp` 덮어쓰기로 후보를 시험한다.
- 설정에 적혀 있다고 적용된 것이 아니다(`D5`). 빈 환경변수가 «차단»처럼 보인다.

## H. 평가·판단 위생

- 🔴 **측정 전에 결론 내지 않는다.** «복구»를 1회 성공으로 선언하지 않는다.
- 🔴 평가 질의·정답을 시스템의 구조로 정의하면 순환이다. 구간이 0을 포함하면 «불확실».
- 사람 평가자 1명·질의 20건은 방향성일 뿐이다.
- 시뮬레이션의 클라이언트 모델이 실제 사용자 모델과 다르면 절대 수치를 믿지 않는다.
- 사전등록한 기준을 결과를 본 뒤에 바꾸지 않는다. 실패한 시험도 보고한다.

## I. 개인정보·보안 위생

- 개인정보는 적재 시점에 마스킹하고, 반환 시점에 한 번 더 가린다. 탐지 한계(이름·주소·계좌)를 문서에 명시한다.
- 키는 해시로만 보관하고, 원문은 1회만 표시한다. 질의 로그에 키 형식 문자열이 남지 않도록 키 패턴을 **먼저** 가린다.
- 서브에이전트·시험 도구에 비밀값을 넘길 때는 파일·로그에 남기지 않는 파이프로만 전달한다.
- 읽기 전용 DB 롤과 앱 롤을 분리하고, 앱 경로에서도 트랜잭션을 READ ONLY 로 강제한다.
- DB 오류 메시지를 사용자에게 그대로 내보내지 않는다(일반화).

## J. 법령 코퍼스 보강에서 알게 된 함정 (2026-11-26)

- 🔴 **법제처에서 같은 법령 일련번호(lsiSeq)에 시행일이 다른 판이 여러 개 있을 수 있다.** 시행일(`efyd`)을 보지 않고 첫 항목을 고르면 현행이 아닌 판이 «현행»으로 들어간다 → 현행 판은 시행일 기준으로(`drf_efyd`) 선택한다.
- 🔴 **구법명 인용은 해소되지 않는다.** 내규가 개명 전 법령명(예: 사내근로복지기금법 등)을 인용하면 «법령명 + 제N조» 매칭이 실패해 `get_related`·인용 링크에서 누락된다. 개명·폐지 법령명 사전이 필요하다(미구현).
- 🔴 **법령 약칭 사전이 없다.** `documents.alias` 가 법령 전체에서 NULL 이라 약칭 질의는 정식 제목 유사도에 의존한다(약칭 백필 스크립트는 manifest 약칭이 있을 때만 채운다).
- 정본(현행)과 연혁은 정의가 다르다. 집계할 때 어느 정의인지(`edition_status`, 연혁 포함 여부, 연도 하한)를 함께 적는다.
