# 02. 수집 원리

> 기준일 2026-11-26. 수집기 소스는 별도 오픈소스 **crawl4alio**(MIT)로 공개되어 있어 이 저장소에 복사하지 않았다(저장소 주소는 미확인). 여기서는 원리와 운영 규칙만 적는다. 내부 호스트·IP·경로·계정은 일반화했다.

## 1. 무엇을 수집하나

| 갈래 | 대상 | 방법 |
|---|---|---|
| 표준 공시 | ALIO 의 공시 항목(분기·연·수시) 문서와 첨부 | ALIO 공개 목록·상세 페이지 + 첨부 다운로드 |
| 게시판형 공시 | 항목 구조가 아닌 게시판 형식 공시 | 게시판 목록·상세 크롤 |
| 채용 | 채용 공고 | **공공데이터포털 공개 API**(목록·상세). 첨부는 별도 다운로드 경로 |
| 기관 내규 | 기관별 취업규칙·인사·보수 규정 원문 | 내규 공시 항목의 첨부 |
| 법령 | 근거 법령(법률·시행령·시행규칙·행정규칙·지침) | **법제처 국가법령정보 공개 API**(DRF) |

채용을 스크래핑에서 공개 API 로 전면 교체한 것은 2026-08-02 이다(목록 `list`, 상세 `detail`; 상세의 식별 파라미터 이름이 `sn` 이라는 점이 함정이었다).

## 2. 정기 vs 수시, 그리고 «회차»

ALIO 공시는 주기가 다르다(수시·연·반기·분기). 이 프로젝트의 점검 «프로필»은 ALIO 의 주기 구분과 **같지 않고**, 실측한 연간 게시 건수를 기준으로 한다.

| 프로필 | 의미 | 점검 방식 |
|---|---|---|
| `quarterly` | 분기 서식(12종) | 분기 지도(어느 분기가 게시되었나) |
| `annual` | 연 1건 안팎(28종) | 기관당 멀티 호출로 서식별 최신 1건 대조 |
| `multi` | 연중 다회(14종) | 전체 이력 조회(14일 순환 샤드) |
| 수시 목록형 | 이사회·감사보고·임원현황·노사협의회 등 15개 코드 | 목록 전수 대조 |

중요한 사실 세 가지:

1. **«최근 공시 feed»(`findDisclosureList`)에는 수시공시만 흐른다.** 정기공시 게시 여부는 항목 API 를 직접 조회해야 알 수 있어서, 새 분기 게시를 보는 **분기공시 감시**(매일 09:00, 알림 전용)를 따로 둔다. feed 는 `endNum` 을 키워도 약 이틀(929건)까지만 준다.
2. **한 해에 같은 항목이 여러 번 올라오는 공시**(예 노사협의회 회의록)는 폴더가 겹쳐 서로 덮어쓰는 문제가 있었다. 그래서 **회차를 구분하는 경로**를 쓴다. 분기 서식은 상세 조회에 항목 **루트 코드**(예 20201)를 넘겨야 하며 분기 서식 코드(20202)를 넘기면 장애 페이지(HTTP 200, 약 1.2KB)가 와서 조용히 건너뛰게 된다.
3. **기준연도는 둘이다.** 정원·현원 같은 시점 값은 «최신 분기», 보수·채용 같은 연간 실적은 «완결 연도»다. 섞으면 조용히 틀린다. 검색 응답의 `period_label`(제출 회차 라벨)과 `report_period`(보고 대상 기간)가 다른 이유도 같다([06](06_search_serving.md)).

## 3. 수집 슬롯과 페이싱

- 일일 슬롯 3개(KST): **07:00 a(전체) · 12:00 b(입찰 경량) · 19:00 c(전체)**. 이전 방식(새벽 03:05 단일 실행)은 2026-10-21 에 슬롯 방식으로 바꾸었다.
- 슬롯 래퍼는 선행 회차가 있으면 **최대 90분** 기다리고, 넘으면 건너뛰며 알림을 보낸다. 가용 메모리가 2GB 미만이면 시작하지 않는다. 정지 표식 파일이 있으면 중단한다.
- 회차 내용: 수시 15개 코드 목록 재조회 → 게시판 전 폼 수집·병합 → 법령 감시 → 내규·수시 재대조.
- **페이싱**: 요청 사이 **고정 간격 + 무작위 지터**를 둔다(현행 값은 간격 약 1.7초 + 지터 최대 약 1.3초, 회선별 설정 파일). 시간당 요청 예산은 서버별 카운터 파일로 센다(기록된 예산 2,400건/시간). 응답이 막히면 속도를 올리지 않고 **멈춘다**. 차단을 우회하는 장치는 두지 않는다.
- **회선 모드**: 레인(동시 작업 수)은 회선 상태에 따라 3(단일 회선) 또는 6(보조 회선 정상 시)이다. 현재는 단일 회선 3레인이며, 이 경우 전체 슬롯 수집이 약 5.5시간(11-22 실측 329분) 걸린다. 회선별 상한을 지키는 것이 목적이지 상한을 넘기기 위한 장치가 아니다.
- 실측에서 얻은 교훈: 과거 차단은 «평균 요청률 초과»가 아니라 **통제 밖 수집기(채용·게시판)의 버스트**가 원인이었다. 그래서 모든 수집기가 같은 요청 예산 관문을 지나도록 했다. 로그 줄 수와 요청 수는 다르다(재시도·리다이렉트).

## 4. 원장(ledger)과 보유 판정

- **보유 판정의 기준은 디스크의 매니페스트(공시번호)다.** 낡은 인덱스 파일로 판정하면 디스크에 있는 공시를 «누락»으로 센다(2026-10-02 실측: 2026년분 93%가 거짓 누락). 시작 때 보유 목록을 새로 만들고 실패하면 수집하지 않는다.
- **항목별 원장**: (기관 × 서식 × 연도) 1행, 열은 보유 수·ALIO 수·차이·상태(`ok`·`gap`·`verified_latest`·`unverified`·`stale`·`incomplete`). 원장은 파생·읽기 전용이며, 완료 판정은 체크포인트가 아니라 원장 상태로 한다.
- **검증 게이트**: 콘텐츠와 매니페스트의 짝을 확인한다. «공시는 받았는데 첨부 하나가 빠진» 구멍은 일반 대조로는 보이지 않아, 월 1회 첨부 단위 대조(읽기 전용, 약 50분)를 돈다.
- 수동으로 raw 를 쓰면 **반드시 원장에 남긴다**(11-17 사고: 원장에 없는 파일이 순회 경고를 만들었다).
- **raw 아카이브**: 원본(raw)은 파생물이 아니라 재처리의 원천이므로 변환·재처리가 끝나기 전에는 삭제하지 않는다. Markdown(md)과 DB 는 raw 에서 재생성할 수 있어야 한다.
- **동결 규칙**: raw 동결은 «수집 종료 후», md 동결은 «변환 현황을 보고 사람이 정한다». 명시 전에는 동결·병합·스테이징을 하지 않는다.

## 5. ZIP 해제

- ZIP 은 **수집이 풀지 않는다.** 해제는 변환 선행의 별도 단계(`extract_zips`, 상한 3,600초)다. 이 단계를 빼면 zip 안의 문서가 변환 입력에서 **조용히** 빠진다(발견 당시 91건 적체).
- 중첩 zip 은 1회 패스로 끝나지 않는다. 바깥 zip 을 처리하다 안쪽 zip 이 먼저 격리되는 문제와 한글 파일명 깨짐(cp949)을 겪었다.
- 해제 파일은 원장에 `src:zip_extract` 로 남긴다. 원본 삭제는 해제 성공을 확인한 뒤에만 한다.
- 압축 폭탄(엔트리 한도 500 고정 등)은 결정론적 실패로 영구 처리한다([03](03_conversion.md)).

## 6. 법제처 법령 수집

- 법제처 공개 API(DRF)로 법령 본문·연혁·시행일·소관부처를 받는다. 호출 식별값(OC)은 환경변수로만 받고 소스에 두지 않는다.
- 법령은 **판본(연혁)** 개념이 있다. 시행일자·법령일련번호(MST)를 받아 «현행/시행예정/연혁/폐지»를 판정하고, 문서마다 `effective_from/to`, `repealed`, `lineage_*` 를 남긴다([04](04_load_embedding.md), [06](06_search_serving.md)).
- **별표·서식은 GFM 표로** 보존한다(별표 hwp 를 kordoc gfm 으로 변환해 본문에 `## 별표·서식` 절로 붙인다). 수집기의 인라인 박스 문자 표는 쓰지 않는다. 별표가 없으면 조문 외 근거가 사라지기 때문이다.
- **법령 개정은 사람 승인 뒤에만 반영한다.** 월 1회 개정 감시가 변경 목록을 만들고, 승인 요청(텔레그램 버튼)을 보낸 뒤 승인되면 `sync_legal --apply` 를 실행한다(승인 요청은 48시간 만료).
- 지침 게시판처럼 개정 판본을 쌓아 두는 곳은 «지침별 현행 1판»만 남기기로 한 적이 있다(2026-08-18, 457 → 402 문서).

## 7. 한계 (정직하게)

- **«누락 N건»은 항상 상한이다.** 점검 도구의 정의에 따라 크게 달라진다(예: 수시 15개 코드를 정기 매트릭스 기준으로만 «완료»라 보고했다가, 목록 전수 대조에서 로컬 보유가 약 절반뿐임이 드러난 일이 2026-10-11 에 있었다). 수시 코드와 정기 코드는 분리해 보고한다.
- 목록 절단 오류가 전수 열거가 끝난 기관에서는 누락이 아니다. 반대로 첨부 단위 구멍은 일반 대조에 안 보인다.
- 이미지(.jpg) 첨부는 텍스트 색인이 되지 않는다(변환 라우팅 밖). 이미지만 있는 공고는 검색에 안 잡힌다.
- DRM 문서·HTML 위장 문서·손상 문서는 변환할 수 없다([03](03_conversion.md)).
- **중복·dup_group**: 같은 문서가 회차마다 재게시되는 경우가 많다(본문 중복 28.1%, 2026-09 실측). 정책은 «전량 색인 + 같은 기관 안 동일 문서만 묶어 표시»다(`dup_group`, 검색 응답의 `same_doc`). 다른 기관 사이는 절대 묶지 않는다. 색인에서 빼면 별칭 경로·회차 질의가 사라져 축소 오류가 생기기 때문이다. 파싱은 해시당 1회만 하고 사본에는 결과를 복사한다.
- 수집 지연: 신규 공시는 다음 슬롯·새벽 델타를 거쳐 반영되므로 하루 정도 늦을 수 있다.
- ALIO 사이트 구조나 이용 조건이 바뀌면 수집이 멈출 수 있다. 이용 조건 관련 확인 사항은 [NOTICE](../NOTICE.md)에 있다.
