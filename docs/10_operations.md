# 10. 운영

> 기준일 2026-11-26. 내부 호스트명·IP·경로·계정은 일반화했고, 비밀값·키·연락처는 싣지 않았다. 운영 상태(어떤 플래그가 켜져 있는지, 가드의 on/off 등) 중 이 자료에서 확인하지 못한 것은 «미확인»으로 표시한다.

## 1. 일일 체인

```
07:00 슬롯 a(전체)  ┐
12:00 슬롯 b(입찰)  ├─ 수집 회차 → 변환(슬롯 종료 직후 자동 연결)
19:00 슬롯 c(전체)  ┘
04:35 새벽 델타   : 어제 04:35 이후 바뀐 md → 파싱 → 문서 단위 교체 적재 → 신규 임베딩
05:00~ DB 물리 백업(2026-11-23 첫 실행 예약, 정기화는 복원 시험 성공 후 별도 승인)
06:45 아침 보고 · 06:50 델타 데드맨 점검 · 06:55 내규 법령정합 일일 갱신
매 10분 검색 워밍·상시 점검 기록 · 5분 감독기(상주 루프 재기동·변환기 가드)
매월 2일 첨부 단위 대조(읽기 전용, 약 50분) · 월 1회 법령 개정 감시 · 매일 09:00 분기공시 감시
```

- 모든 단계는 **표식 파일**로 멈춘다(`STOP` = 즉시 전체, `STOP_ROUND_SLOTS`·`STOP_DAILY_CONVERT`·`DELTA_HOLD` = 해당 단계만). 크론은 표식이 있는 채로 먼저 설치해도 안전하고, 표식은 점검을 마친 뒤 승인 범위만큼 해제한다. 감독기는 해제된 루프를 5분 안에 되살리므로 해제 직후의 영향을 의식한다.
- 슬롯 b(12:00)는 선행 회차를 최대 90분 기다리고, 넘으면 건너뛰며 알림을 보낸다. 단일 회선 3레인이면 슬롯 a 가 약 5.5시간이라 b 가 건너뛰어질 위험이 확인되었고 대책(크론 시각 이동 또는 병행 회선 복구)은 결정 대기다.
- 새벽 델타의 임베딩은 GPU 서버 샤드로 나눠 처리하고, 가용 메모리가 부족하면 임베딩만 이월한다.
- 주간 재생성: 월요일 06:10 에 웹 산출물(요약 JSON 등)을 샌드박스에서 다시 만들어 지난 전달본과 다른 파일만 전달한다(운영 파일·DB 는 바꾸지 않음, 지문 비교, 검증 실패 시 전달 안 함).

## 2. 모니터링·알림

| 항목 | 방식 |
|---|---|
| 알림 경로 | 웹훅(워크플로 자동화 도구) → 메신저. 슬롯 비정상 종료·델타 실패·건너뜀·워커 사용 불가 |
| 실패 유형 구분 | 영구(DRM·손상·압축 폭탄 등)와 일시(통신·시간 초과)를 나누어 **실패율 경고는 일시 유형만** 계산 |
| 데드맨 | 06:50 에 새벽 델타 결과 부재·미임베딩 정체를 점검. 월요일에는 주간 변환 현황 |
| 진행 판단 | 진척은 «산출 개수»가 아니라 «훑은 범위»로 센다(멀쩡한 레인이 죽은 것처럼 보이지 않게). 프로세스 생사는 `kill -0` 단독이 아니라 상태까지 본다(좀비 PID 오판 사례) |
| 정상 기준선 | 이상 판정 전에 정상일 때의 값을 먼저 기록해 비교한다 |
| 로그 시간대 | 컨테이너 로그는 UTC, 운영 문서는 KST. 창 필터가 조용히 전부 버리는 일을 막기 위해 표기를 구분한다 |

## 3. 키 발급·한도

- **접속 키**가 있어야 서비스에 접속할 수 있다(익명은 401). 서비스 안내 페이지에서 신청한다.
- **자동 신청**: 소속기관·이메일(필수), 이름·목적(선택), 개인정보 수집·이용 동의. 공공·연구·학교 도메인 이메일은 메일 링크에서 바로 키를 받고, 그 밖의 이메일은 운영자 승인 뒤 안내 메일이 간다. 안내 메일의 링크는 **12시간 안에 한 번만** 열 수 있고, 메일 자체에는 키가 들어 있지 않다. 유효기간: 자동 신청 15일, 수동 발급 기본 90일(2026-11-02 안내 기준). 발송한 안내 메일 사본은 자동 삭제 규칙으로 16일 뒤 지운다.
- **키 저장**: 서버에는 키의 **sha256 해시만** 둔다(만료·폐기 지원, 원문은 발급 때 1회만 표시). 키 파일이 손상되면 fail-closed(모두 거부).
- **한도**: 기본 분당 40회, 의미·하이브리드 분당 10회(전역값). 키에 `limits`(분당·의미 분당·일일·의미 일일·배치)가 있으면 그 키는 IP 가 아니라 **키 ID** 기준으로 센다. 일일 카운터는 한국시간 자정에 초기화되며 작은 JSON 파일에 주기 저장(손상 시 «카운트 0 에서 시작»). 무거운 도구는 도구별 추가 한도([07](07_mcp_tools.md)). `find_citing` 은 동시 실행 4건 상한이다. MCP 도구는 14개이며(2026-11-26 c15, `find_citing` 추가) 일부 도구는 플래그·등급별로 노출을 끈다. 한도 초과는 429 + `Retry-After`.
- **등급**: `master`(원문 확인 가능 — 마스터 키), `internal`(서버 내부 호출: 루프백 등 허용 대역 또는 서비스 토큰), `external`(발급 키). 내부 포트는 «포트 번호만으로» internal 로 보지 않고 요청 원본 주소가 허용 CIDR 일 때만 인정한다(같은 컨테이너 네트워크의 다른 컨테이너가 키 없이 internal 이 되던 문제를 고침). 허용 목록에 잘못된 항목이 하나라도 있으면 목록 전체를 무효로 보고 거부한다(fail-closed).
- 공개 모드 플래그가 켜져 있으면 키 없이 익명 external 을 허용한다. 운영 설정 확인이 필요한 항목이다.

## 4. 개인정보 마스킹·등급

| 단계 | 처리 |
|---|---|
| 색인 제외 | 개인 기록 유형(예: 본인 이름이 파일명에 있는 건강검진 문서)은 파싱 전에 제외 |
| **적재 시점** | 청크 텍스트에서 주민번호형·휴대폰·개인 메일 마스킹 → DB·임베딩에 원문이 없다(외부 API 로 임베딩을 보낸 시기에도 원문이 나가지 않음). 원문은 md 파일에만 있고 마스터가 md 로 확인 |
| **반환 시점** | 응답 행·본문·제목을 한 번 더 마스킹. 등급별: external·미지정은 모든 이메일, internal·master 는 개인 포털 메일만 |
| 주민번호형 | 생년월일 유효 + 검증숫자 일치일 때 뒤 6자리 마스킹(법인등록번호 라벨 직전은 제외). 검증숫자가 틀려도 «주민(등록)번호» 라벨이 직전에 있으면 보수적으로 마스킹 |
| 휴대폰 | 01[016789] 가운데 자리 마스킹, 앞뒤가 숫자·영문·하이픈이면 제외(코드 `A010-…` 보존) |
| 질의 로그 | 질의 문자열에서 전화·주민·사업자번호는 통째로, 이메일은 전부, 7자리 이상 숫자열을 마스킹한 뒤 200자로 자른다. 키·긴 16진 해시 패턴을 **먼저** 가린다(숫자 12자 이상이 이어진 키가 먼저 쪼개져 일부가 남던 누출을 고침) |
| **한계** | **이름·주소·계좌번호는 탐지하지 못한다.** 일반전화는 긴 숫자열·품목코드에 과다 적중(약 33만 건)해 마스킹하지 않는다. 질의 속 «이름»도 탐지 불가. 공개 서비스라서 문서와 응답에 이 한계를 명시한다 |

## 5. 질의 로그 정책

- 목적: 독립 평가 집합, 0건·실패 패턴, 지연 분포. **모델 학습·외부 전송·개별 사용자 추적에는 쓰지 않는다.**
- 기록(필드 화이트리스트): 분 단위 시각, 도구, 등급, 클라이언트 라벨(키 «이름»), 코퍼스, 모드, **마스킹된 질의(≤200자)**, 필터 값, 건수, 상위 3 doc_id, 지연, 경고. `query_sql` 은 정규화 SQL 과 해시만.
- **미기록**: IP·키 값·키 해시·토큰·User-Agent·헤더·응답 본문·제목·실명. 라벨 ↔ 사람 매핑은 로그와 분리 보관.
- 쓰기: 응답 뒤 비동기 → 메모리 큐 → 배치 append. 실패·큐 초과는 삼키고 경고 1줄(서비스에 영향 없음).
- 보존: 접속 로그 약 30일, 질의 로그 90일(이후 집계만), 감사 로그 1년 정리 규칙(처리방침 약속과 실제 설정이 어긋나지 않게 유지). 질의 로그 활성화는 승인 사항이었고 한동안 보류했다.
- 매주 월요일 오전 사람 1명이 주간 리포트·실패 질의 큐를 약 30분 검수하고, 동의어 후보는 승인된 것만 운영 사전에 반영한다.

## 6. 서빙 배포와 롤백 원칙

- **이미지 오버레이 빌드**: 서빙 컨테이너는 바인드 마운트가 아니라 이미지에 코드를 `COPY` 한다. 코드를 고치면 새 이미지를 빌드해야 반영된다. 새 이미지는 «기존 이미지 위에 변경 파일만 덮는» 오버레이 방식으로 만들고 태그를 날짜+순번으로 붙인다(예: `dev-20261126c15`).
- **기능 플래그**: 신규 기능은 환경 플래그가 꺼져 있으면 응답이 종전과 바이트 동일하다. 롤백은 ① 플래그 off(재기동) ② 이전 이미지 태그로 복귀. 두 경로 모두 즉시 가능해야 하며, **이미지가 사라지지 않았는지**를 먼저 확인한다(컨테이너 교체 뒤 구버전 이미지가 사라진 사고).
- **후보 시험은 별도 시험 컨테이너**에서 한다. 운영 컨테이너에는 시험하지 않는다.
- 배포 스크립트는 백업을 무조건 덮어쓰지 않고, 치환마다 단언(assert)하며, 시험 뒤 즉시 검증한다(레드팀이 짚은 결함).
- 운영 DB·컨테이너·compose 변경은 사람 승인 사항이다. 평가·점검은 읽기 전용 경로로만 한다.
- 가동 중인 셸 스크립트를 제자리 수정하면 끝부분이 문법 오류로 죽는다 → 사본 수정 후 원자적 교체(`mv`)한다.

## 7. 정리 규칙

- 백업·시험 테이블(`*_bak_*`)·구버전 파일은 **승인 없이 지우지 않는다.** 삭제 전에 참조 여부(뷰·스크립트)를 확인한다.
- 대량 삭제·재생성 전에 스냅샷(스키마·건수)을 남긴다. 고아 벡터 정리는 HNSW 를 내린 상태에서 한다.
- 임시 시험물은 시험 폴더에 두고 끝나면 정리를 요청한다. 키·토큰이 들어 있는 시험용 사본은 사용 후 즉시 삭제 대상으로 표시한다.
- 심볼릭 링크 디렉터리를 `rm -r` 하면 대상 원본이 지워질 수 있다(사고 사례) — 임시 복사는 링크를 따라가 복사(`cp -rL`)하고, 삭제 전에 링크 여부를 확인한다.
- 수동으로 raw 를 쓰면 원장에 남긴다. 복사·이관 시 mtime 을 보존한다(델타 선별이 mtime 기반).

## 8. 알려진 제약 (2026-11-26)

- DB 정기 백업: 2026-11-22 문서 기준으로 첫 물리 백업을 예약했고 정기화는 복원 시험 성공 뒤 별도 승인이다. 그 이후의 진행은 확인하지 못했다(미확인).
- 법령 개정 승인 대기 목록이 쌓여 있을 수 있다(사람 승인 필요).
- 질의 로그·서빙 가드·일부 플래그의 현재 on/off 상태는 이 문서에서 확인하지 못했다.
