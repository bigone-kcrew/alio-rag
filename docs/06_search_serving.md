# 06. 검색과 서빙

> 기준일 2026-11-26. 근거: `src/serving/`(운영 MCP 컨테이너 `/app` 에서 복사한 현행 코드), 운영 기록. 기능 대부분은 **환경 플래그가 켜져 있을 때만** 동작하며, 꺼져 있으면 응답이 종전과 바이트 동일하다. 어떤 플래그가 운영에서 켜져 있는지는 이 저장소에 값을 싣지 않았다.

## 1. 검색 모드

| 모드 | 인자 | 동작 |
|---|---|---|
| 키워드 | 기본 | 제목은 trigram 유사도, `body=true` 면 본문 `lower(body) LIKE`(pg_bigm 2-gram). 짧은 명사·3자 이상 권장 |
| 의미 | `semantic=true` | 질의를 임베딩해 HNSW 후보 → 원본 벡터 정확 재순위. 문장형은 의미 팔이 더 맞다 |
| 하이브리드 | `hybrid=true` | 키워드 + 의미를 **RRF**로 융합한 단일 검색. 의미 팔이 실패하면 키워드로 강등하고 `degraded` 를 단다 |

### 융합: Reciprocal Rank Fusion

`score(d) = Σ 1 / (K + rank_i(d))`, **K = 60**. 점수 체계가 다른 두 목록(trigram 유사도 vs 코사인)을 정규화 없이 순위만으로 합친다. 같은 문서의 여러 청크가 한 항목으로 합쳐져 점수가 쌓이지 않도록 키는 «조각(청크) 단위»다.

- **융합 v2(`SEARCH_FUSE_V2`)**: 질의 유형에 따라 키워드 쪽 가중·순서를 바꾸는 후보(문장형 판정 등). 2026-11-25 시험에서 hybrid 개선(+0.126, 67줄 변경)이 확인되어 11-26 운영 이미지에 반영되었다(플래그 on).
- **자동 모드(`SEARCH_AUTO_MODE`)**: 모드를 지정하지 않은 문장형·의문형 질의(공백 2개 이상 또는 의문 어미)를 단일 코퍼스에서 hybrid 로 승격한다. 법령·규정명 단독 질의(예 «○○법», «○○ 시행령»)와 `body:true` 명시는 키워드를 유지한다. 키워드 0건이면 hybrid 로 한 번 더(옵션) 시도하고 0건 사유 코드·기관별 보유 현황을 싣는다.
- 의미 검색의 필터 질의는 **2단계**다. 먼저 필터 조건으로 후보 id 를 줄이고, 후보가 `SEMANTIC_EXACT_MAX`(2만) 이하이면 HNSW 대신 정확 거리로 계산한다. 선택적 필터가 HNSW 에서 최대 약 7초 걸리던 것을 약 0.3초로 줄였다. 후보가 0이면 임베딩 호출 없이 즉시 응답한다.
- 코퍼스 `all` 은 4개 코퍼스를 병렬 질의하고 동점은 라운드 로빈으로 섞는다.

## 2. 질의 이해

| 요소 | 방식 | 비고 |
|---|---|---|
| 기관명·약칭 | 입력 **전체**가 약칭 사전과 정확히 같을 때만 정식명으로 바꾼다(`inst_alias`). 정식명 부분일치 필터라 약칭이 0건이 되는 것을 막는다 | 사전은 JSON 데이터 파일(30초마다 mtime 확인해 핫리로드). 이 저장소에는 데이터를 넣지 않았다 |
| 결정론적 가제티어 | 기관·연도·활용처 키워드를 추출하고 나머지를 잔여 검색어로 둔다. **LLM 아님 — 같은 질의는 항상 같은 결과** | 의도 라벨(조문·비교·집계·사례·검색)은 힌트용이며 오분류해도 검색은 불변 |
| 동의어·부처 구명칭 | `expand=true` 일 때 사전 묶음으로 변형 질의(최대 6개)를 만든다. 원문은 포함하지 않는다 | 1쪽만, `expanded_terms` 응답 |
| 항목(공시 항목) 해석 | 자연어 항목명·별칭·코드를 항목 카탈로그로 코드 목록으로 바꾼다(`item_filter`). 모드 `off|explicit|auto` | 사전 파일은 데이터라 미포함. `list_catalog(kind=items)` 로 확인 |
| 활용처(usecase) | `recruit·audit·governance·labor·finance·welfare·safety·security·esg` 태그 필터. 문서에 태그가 있는 경우만 통과(kNN 태깅으로 확장) | 알 수 없는 값은 0건 + `usecase_warning` |

## 3. 판본·시점 처리

- **기본 = 현행판만.** 법령·지침은 `edition_status` 표식, 내규는 적재 때 계산한 판본 표식(구 DB 호환으로 같은 기관+같은 제목에 `doc_date` 가 더 큰 형제가 있으면 구판), 폐지 법령은 기본 제외, 시행예정은 제외.
- `all_versions=true`: 연혁·시행예정·폐지 포함. `as_of=YYYY-MM-DD`: 그 날짜에 유효한 판(`effective_from <= as_of < effective_to`). `all_versions` 와 함께 쓰면 `all_versions` 가 우선.
- 각 행의 `edition_state`(`current|superseded|scheduled|repealed|lineage_closed`)·`edition_warning`(현행이 아닐 때만)·`effective_from/to`·`section` 을 답에 명시해야 한다.
- **단체협약**의 현행 판정은 «기관·협약 경로 기준 최신 폴더 연도»로 **근사**한다(문서 날짜가 없어서). 응답에 `edition_basis=folder_year_approx`.
- 같은 문서의 여러 판본 중 정답 판본을 고르는 규칙은 `editionTieOrder` 로 결정론적이다.

### 공시의 두 가지 «기간»

| 필드 | 의미 |
|---|---|
| `period` / `period_label` | 공시 **회차(제출)** 라벨. 1~3월에 제출한 4분기 보고서는 다음 해 라벨이 붙는다. 회차마다 과거 연도 첨부가 재게시된다 |
| `report_period` / `period_label_adj` | **보고 대상** 분기·연도(1~3월 제출 4분기 보고서는 전년 4분기로 보정) |
| `target_year` | 문서 제목의 «20XX년» — 재게시되는 과거 연도 첨부를 거르는 용도 |
| `submitted_at` | 공시일 |

`period_semantics` 필드가 이 설명을 한 줄로 붙여 준다. `series_latest=false` 는 «같은 기관·항목에 나중 공시가 있다»는 뜻일 뿐 이 행이 틀렸다는 뜻이 아니다. «최신·현재» 질문이면 나중 공시를, 특정 기간이면 그 기간 행을 쓴다. 계열 키는 «항목명 + 주기(분기/연)»다(항목명만 쓰면 하위 항목이 합쳐져 오표시가 3,239건 났다).

## 4. 중복 접기(dup_group)

- **같은 기관의 동일 문서(회차 재게시)**를 대표 1건으로 접고 `same_doc.rounds[].period_label` 로 다른 회차를 알린다(`collapse_dup`, 기본 true, `false` 로 끔). **다른 기관 사이는 절대 묶지 않는다.**
- 접기 정책 A: 접기 키는 불변, `same_doc` 에 분기 목록만 추가한다(2026-10-22 결정).
- `distinct_inst=true`: 기관당 상위 1건만 반환해 `limit` 개 기관까지(기관 단위 집계). `deduped_from` 로 중복 제거 전 후보 수를 알린다.

## 5. 재랭크

| 대상 | 상태 | 조건·결과 |
|---|---|---|
| **법령** | **적용 중**(MCP 경로만) | `corpus=legal` 명시 + `semantic=true`(hybrid 아님) + 후보 2건 이상 → 상위 10건을 재정렬. 모델 KURE-Reranker-nano(int8). 사전등록한 법령 test 32건 판정 통과: hit@1 0.219 → 0.531, MRR 0.349 → 0.573, 서버 p95 2.2초 |
| **내규** | **그림자(적용 안 함)** | 점수만 계산해 로그를 남기고 응답·순서는 불변. 사용자 대기 없음(비동기). 3일·200건 판정 뒤에만 적용 여부 결정. 로컬 사이드카 서버를 쓴다 |
| 그 밖 | 미적용 | 전체 코퍼스 semantic 기준 효과가 없었고 내규 hit@1 이 유의하게 하락했다. hybrid 법령은 test 미검증 |

- 실패·타임아웃(5초)·차단기(3회 실패 → 30초)·캐시: 항상 «원순위 + `rerank:{applied:false, reason}`». 꺼져 있으면 응답에 `rerank` 키가 아예 없다.
- 지연: 법령 semantic 은 재랭크로 +1.3~1.9초.
- 외부 API 를 쓰지 않고 로컬 서버에서 실행한다(검색어·문서 본문의 외부 전송 없음).
- 초기에 외부 호스팅 재랭커(NVIDIA)도 시험했으나 n=30 에서 구간이 0을 포함해 불확실했고, 외부 전송·약관 문제로 채택하지 않았다.

## 6. 그 밖의 서빙 로직

| 기능 | 내용 |
|---|---|
| 표 머리글 | 공시 표 청크에 1번 청크의 열 이름 줄을 `table_header` 로 붙인다(청크만으로 열 의미를 알 수 없어서) |
| 껍데기 문서 | 본문이 없는 공시 페이지(`content_chars<60`)를 첨부 문서로 대체·병합·숨김(플래그별). 채용 공고는 오대체 위험으로 대체하지 않고 후보만 안내 |
| `docs_total` | 구조 필터를 만족하는 공시 문서 수(키워드 무시, 상한 5,000) |
| `zero_reasons` | 0건일 때 이유 후보(필터 과다·period 라벨 불일치·키워드 모드 한계) |
| 공개 전 표기 | 상태 파일 기준으로 «공개 전(pre_release)» 공시에 표식. 상태 파일이 없거나 오래되면 표기하지 않는다(공개 후에도 «공개 전»이라 말하는 것 방지) |
| 검색 결과 캐시 | `SEARCH_CACHE=on`: 정규화 질의 + 모든 인자 + **코퍼스 변경 카운터 스탬프**가 키. 일일 델타가 끝나면 스탬프가 바뀌어 저절로 무효화. TTL 법령·내규·단협 24h, 공시 6h. 스탬프를 못 읽으면 캐시를 쓰지 않는다(fail-open) |
| 페이징 | `search_corpus` 는 `offset`, 응답 `has_more`·`next_offset`·`window_exhausted`. 볼 수 있는 범위는 앞쪽 약 200건 |
| 응답 크기 | 60,000바이트 초과 시 경고(`MCP_RESPONSE_WARN_BYTES`). 도구 설명 길이도 «도구 목록 크기 예산» 때문에 일부 도구는 매우 짧다 |
| 순위·최다 질문 | `RANKQ` 정규식으로 «가장·최다·순위» 질문을 감지해 한계 고지를 붙인다(`search_corpus` 의 상위 후보만으로는 전수·순위를 말할 수 없다) |

## 7. 서빙 가드·워밍·캐시 (운영)

- **워밍**: 10분마다 대표 질의를 보내 인덱스·캐시를 데운다(콜드 캐시에서 내규 의미 검색이 15초 제한에 걸린 적이 있다). 워밍 결과 기준선 이력을 파일로 남긴다(11-26 신설 — 그 전에는 덮어써서 기준선을 알 수 없었다).
- **서빙 가드**: 워밍이 느리면 가드 표식을 만들어 변환 작업이 **보조 서버 전용**으로 돌게 한다(검색 지연을 변환이 잡아먹지 않게). 가드가 수집·평가 구간과 겹쳐 평가가 끊긴 적이 있어, 평가 하네스는 별도 승인으로 가드 중단 조건을 둔다. 현재 가드의 on/off 상태는 이 문서에서 확인하지 못했다(미확인).
- **인증·한도**: 등급 `master|internal|external` 과 키별 한도는 [10](10_operations.md). 서버 한도 기본 분당 40회, 의미·하이브리드 분당 10회(MCP 경로도 동일 값), 키에 별도 한도가 있으면 그것을 따른다.
- 반환 마스킹: 응답 행·본문·제목에서 주민번호형·휴대폰·개인 메일을 가린다. `MASK_PII=0` 으로만 끌 수 있고 기본은 켬.
- 모든 질의에는 `statement_timeout` 이 걸린다(도구별 5~15초). 시간 초과는 «좁혀서 다시 시도하세요» 안내로 변환된다.

## 8. 한계

- 키워드 검색은 조사·활용 변형에 약하다(부분일치라 일부는 자연 허용). 같은 뜻의 다른 단어는 의미·hybrid 모드나 `expand` 가 필요하다.
- `count_institutions` 는 «본문에 문구가 있는 기관»을 센다. 제도를 시행하는 기관 수가 아니다(언급·부정문 포함, 모든 판본 기준).
- 의미 검색은 순위가 안정적이지 않고(후보 경계에서 달라짐), 쪽 경계에서 순위가 조금 바뀔 수 있다(쪽마다 새로 검색).
- HNSW 는 근사 검색이다. 내규·법령·단체협약의 recall 은 ef_search=400 에서 정확해 대비 0.95~0.98(스테이징 실측, 내부 보고).
- 공시 코퍼스는 비트 양자화 인덱스를 쓰므로 후보→재순위 단계에 의존한다.
